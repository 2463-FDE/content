Week 5 · Day 4Neo4j Knowledge Graphs & Context EngineeringCore 30 · ~5 min read · 3 min diagram · 1 interaction · 6-Q check · ~19 min required

Turn the graph into bounded agent context: combine Chroma candidates with Neo4j paths, query through a LangGraph node, evaluate grounding, manage latency and cost, review a scoped Neo4j MCP surface, and compare graph placement without provisioning anything.

1 · Required

Institutional memory needs ownership

A knowledge graph can preserve entities, relationships, decisions, and evidence across agent sessions and team changes. Calling it institutional memory is justified only when correction and governance are designed. Every material assertion needs provenance, freshness or effective time, and an owner or source. Superseded facts must remain traceable without being returned as current. Unknown and conflicting evidence must survive context assembly. A graph that only accumulates edges becomes institutional rumor with excellent traversal.

2 · Required

Combine Chroma candidates with Neo4j paths

Use Chroma where semantic similarity finds passages or entities despite varied wording. Use Neo4j where an answer depends on explicit connections such as current rule → exception → owner → escalation. A hybrid path may retrieve semantic candidates, resolve their stable identifiers, traverse only required relationships, then deduplicate and assemble evidence. Do not query both stores by habit. Define what each contributes, what happens when identifiers disagree, and which source owns correction. The required lab makes you choose this bounded hybrid for a mixed semantic-and-path question.

3 · Required

Query Neo4j from a LangGraph node

A LangGraph node can call application code that runs a parameterized, read-only Neo4j query. Keep the node contract narrow: validated input, timeout, database selection, maximum rows/paths, typed evidence output, and explicit error state. Database authorization is enforced by the application and database—not by the model’s intention. Return source IDs, path facts, and limits rather than an unbounded graph dump or a finished answer. The next node can assemble context or choose an abstention path when evidence is missing.

4 · Required

Evaluate grounding in layers

Separate retrieval relevance from answer support. First, did semantic search return the expected candidate? Second, did graph expansion return the expected connected path and current version? Third, does each material answer claim map to retrieved evidence? Fourth, does the agent abstain or surface conflict when support is absent? Track failures by layer so a generation rewrite does not hide a retrieval defect. Use synthetic golden questions and adversarial no-evidence cases. A polished answer with no trace is a failed grounding result.

Required interaction · Context-pack builder
The question uses varied wording and asks for a current exception, its owner, and escalation path. Which context plan is most defensible?

5 · Required

Assemble context for the decision

Context engineering is selection, structure, and limits. Include the question, eligible claims, compact graph paths, source identifiers, freshness, conflict notes, and instructions for citation/abstention. Deduplicate the passage and graph representation of the same fact. Preserve enough path semantics to explain why evidence is connected. Apply a token budget and prioritize decision-bearing evidence over background. More context can increase latency and bury the rule that mattered; a bigger window is not a substitute for an evidence policy.

6 · Required

Make query cost and performance visible

Parameterize queries and select the intended database. Bound variable paths and result counts. Use EXPLAIN to inspect a plan without execution and PROFILE when measured execution is safe; PROFILE executes the query, so never treat it as a harmless preview of a write. Review index use, cardinality, traversal fan-out, driver transaction pattern, timeout, and context-token growth. Reuse old NFR/cost judgment here: latency, operational ownership, data movement, and model tokens are part of retrieval quality.

7 · Required

Use Neo4j through MCP as a scoped tool

A Neo4j MCP server can expose graph operations to Claude Code or another MCP client. Treat it as a tool surface, not an authorization boundary. Allowlist read operations for the lab, use synthetic/local data, keep credentials outside prompts and repositories, and require application/database policy. Review the exact tool schema and returned payload. No MCP connection is performed by this page, and no external action is authorized. The useful retro question is which configuration improved evidence access without widening power.

8 · Required

Compare topology without choosing a cloud path

The source curriculum requires a graph-topology comparison: self-managed Neo4j on EC2 or GCE versus Aura available through AWS or Google Cloud marketplaces; private connectivity; and data gravity. Compare dated eligibility, regions, networking, operational ownership, workload volume, latency, egress, and correction/recovery needs. Marketplace presence proves availability—not price parity, private connectivity, suitability, or a recommendation. This is an architecture worksheet only: no cloud picker, certification objective, account change, provisioning, or deployment. Record unknowns and the evidence that would flip a placement decision.

Grounding scorecard · optional depth

Record candidate recall, path/result correctness, claim support, citation/provenance validity, conflict handling, and abstention behavior separately. One blended score can hide the failing layer.

MCP review checklist · optional depth

Exact tool and operation; caller identity; database/tenant scope; read versus write; arguments; result limit; timeout; audit event; secret location; denial test. MCP transport does not replace any row.

Topology evidence sheet · optional depth

Compare self-managed and managed options using dated region/eligibility, private-network pattern, operations owner, data gravity, egress, workload assumptions, normalized cost unit, and flip condition. Leave unknown cells pending rather than filling them from memory.
