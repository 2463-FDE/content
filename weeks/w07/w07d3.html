Alt Research: Langfuse, Phoenix & Helicone against LangSmith

Week 7 · Day 3 Observability & SRE ~25 min · reading @150 wpm + diagram + check

Every other day this week is about the client's system. Today is about the platform the client will pay for. Day 1 gave you traces and spans; the moment you show a tracing plan, someone asks where that data goes, who owns the tool, and what it costs. Four serious answers exist — LangSmith, Langfuse, Arize Phoenix, and Helicone — and they differ on six axes that have nothing to do with which dashboard is prettier: deployment topology, how OTel-native they really are, license, pricing meter, data residency, and vendor continuity. Your deliverable is not a favourite. It is a one-page memo an exec signs: options, one recommendation, and the single client constraint that decided it.

The deliverable

You are not picking a tool. You are writing a memo.

Start with the output, because it changes how you read everything else. The artifact is one page: Decision, Options considered — each rejected one carrying the fact that disqualified it — Recommendation, the constraint that decided it, Cost at an assumed volume, Reversibility, What we're accepting. An exec signs that. Nobody signs a feature-comparison table.

The spine of the memo is one constraint. Not seven. A memo listing eleven considerations of equal weight has not made a decision; it has forwarded the decision back to whoever asked you. The craft move is to find the single client fact that eliminates most of the field, name it in one sentence, and let everything else be supporting detail. Healthcare's sentence is "intake traces contain PHI." Finance's is "this reconciliation is a SOX-material control and its evidence must survive an audit period."

Second rule, and it separates a professional memo from a plausible one: every price and every capability claim carries a source and a verified date. All four vendors below changed something material in the last year — a licence you'd misremember, an acquisition, a pricing unit that no longer exists, a major-version data-model change. Anyone answering from memory gets at least one wrong, and a wrong fact in a signed memo costs you credibility, not a footnote. Today you practise verifying instead of recalling.

Axis ① · topology

Where the trace payload lives eliminates the field fastest

Run this axis first because it is binary and cuts hardest: can trace payloads leave the client's network? Five real topologies — managed SaaS, region-pinned SaaS, hybrid (SaaS control plane, self-hosted data plane), self-hosted, air-gapped — and the four vendors land in very different places.

Phoenix is the most permissive: free to self-host with no feature limitations, "nothing is sent to Arize," fully air-gappable, with deployment paths from a CLI through Docker, Kubernetes, Helm, CloudFormation and Cloud Run — and OAuth2/LDAP auth, RBAC and retention policies in the free product. Langfuse self-hosted runs the same codebase as its cloud, deployable in a VPC or on-premises where "internet access is optional" — but the honest cost is that it is five components, not one container: Langfuse Web and Worker plus Postgres, ClickHouse, Redis/Valkey and S3-compatible blob storage. Plus an operational trap worth quoting to whoever runs the cluster: all infrastructure must run with its timezone set to UTC, or queries silently return incorrect or empty results.

LangSmith gates self-hosting to Enterprise, and it is not air-gapped by default. The install docs require egress to beacon.langchain.com, and the egress page is explicit that this covers billing telemetry — licence verification and usage reporting — which cannot be disabled. A true offline install needs a separately negotiated air-gapped licence, and enabling Engine adds a second destination through which "Engine content leaves your environment." LangSmith does offer the genuine hybrid option, though: SaaS control plane, self-hosted data plane. Helicone self-hosts four ways — manual, Docker Compose, Kubernetes, cloud — with Discord-only support on the OSS path.

Axis ② · OTel

"We support OpenTelemetry" tells you nothing

All four ingest OTLP. That sentence is on every marketing page and useless for deciding. What matters is whether the vendor's internal data model is OTel's, or whether OTLP is a translation layer bolted on the front.

Phoenix is the most genuinely OTel-native: built on OpenTelemetry and powered by OpenInference instrumentation, with auto-instrumentation across LangChain, LlamaIndex, the Vercel AI SDK, Bedrock and Anthropic, in Python, TypeScript and Java. Langfuse is an OTel backend with a mapping layer, and says so: because the GenAI semantic conventions "are still evolving," it maps received OTel traces into the Langfuse data model. Two details you will hit in the first hour — it supports OTLP over HTTP/JSON and HTTP/protobuf but gRPC is not supported, and direct senders need the x-langfuse-ingestion-version: 4 header or data can lag by ten minutes. LangSmith is proprietary-model-first with a published translation table (gen_ai.system → metadata.ls_provider, gen_ai.prompt → inputs). Helicone is a different animal: a gateway, not an instrumentation library. Repoint your OpenAI-compatible SDK at ai-gateway.helicone.ai and logging is automatic — but a proxy only sees what crosses it, so retrieval steps, tool calls and agent control flow stay invisible unless you instrument anyway.

Underneath sit two rival convention sets — OpenInference (Arize) and OpenLLMetry (Traceloop), both Apache 2.0 — and the standard they converge on is not finished: the OTel GenAI semantic conventions moved to their own repository where the Schema URL section still reads "TODO" and no releases have been cut. Portability is aspirational today. The consequence for the memo: instrument with a vendor-neutral library and export through an OTel Collector. LangSmith itself documents the Collector fanout pattern — one span stream to several backends at once. The lock-in decision is the instrumentation SDK, not the backend, and fanout makes "trial two vendors for a month" a config change instead of a project.

Axis ③ · license

Four legally different meanings of "open source"

Ask an engineer and you get "three of them are open source." Ask counsel and you get four different answers.

Langfuse is MIT — except the ee/ folders. The repository says exactly that, and the self-hosted OSS tier is unusually generous: all core platform features and APIs, unlimited usage, and — notably — enterprise SSO and RBAC included, which most open-core vendors keep behind the paywall. Helicone is Apache 2.0, with the vendor's stated rationale explicitly naming "preventing vendor lock-in." LangSmith is proprietary, with self-hosting gated to Enterprise behind a network-verified licence key.

And the one nearly everyone gets wrong: Arize Phoenix is Elastic License 2.0, not Apache 2.0. The repository states it plainly and adds a patent notice — portions of the code are covered by U.S. patents. ELv2 is source-available, not OSI-approved: it forbids providing the software to third parties as a managed service, and forbids circumventing licence-key functionality. Read that against your actual engagement. For a client running Phoenix internally on their own traces, ELv2 is irrelevant. For a client whose product is a hosted platform resold to their customers with the observability UI embedded in it, ELv2 is disqualifying. Both sentences belong in the memo, in that order — the exec's lawyer asks the second question and the engineer only prepared the first.

The shape of this axis: don't report a licence, report what it permits for this deployment. "OSI-approved" is a hard procurement gate at some organizations and meaningless at others; find out which kind you're in before you write a recommendation that hinges on it.

Axis ④ · pricing

Four incompatible meters — which is exactly the point

You cannot compare these prices. Not "it's hard" — you literally cannot, because the four vendors bill in four different units. Langfuse Cloud meters "units": Hobby free (50k units/month, 30-day data access), Core $29/month (100k units, 90 days), Pro $199/month (three years of data access, retention management, SOC 2 / ISO 27001 reports, HIPAA-ready region), Enterprise $2,499/month (audit logs, SCIM); overage runs $8 per 100k units, and self-hosted OSS is free with unlimited usage. Helicone meters requests plus storage: Hobby free (10,000 requests, 1 GB), Pro $79/month, Team $799/month (SOC-2 and HIPAA). Arize AX — the hosted path for Phoenix — meters spans, ingest GB and retention window together: Free is 25k spans/month, 1 GB, 15-day retention; Pro is $50/month for 50k spans, 10 GB, 30 days; users and evals are unlimited on every tier. LangSmith has repriced onto normalized units — LCU at $1.50 for work done, LSU at $1.00 for data stored — with Developer at $0/seat (5k base traces) and Plus at $39/seat/month (10k base traces, then 0.005 LSU per additional trace). Flat per-trace numbers you may have memorized are stale.

A unit, a request, a span and an LSU are four different things, and one trace fans out into many spans. So your cost section is invalid unless it states two numbers up front: the assumed monthly volume and the trace-to-span fan-out ratio. Count the spans in the trace you drew on Day 1 and use that.

One more meter hides in plain sight: retention window is a cost axis, not a feature bullet. Fifteen days on AX Free, thirty on AX Pro and Langfuse Hobby, ninety on Core, three years on Langfuse Pro. If the traces are evidence for an audit-relevant control, a control whose evidence evaporates in fifteen days is not a control.

Axis ⑤ · residency

Residency, BAAs, and the controls that shrink what ever leaves

Here is the sentence that decides the healthcare memo: a trace payload containing PHI is a PHI disclosure. Not "logging." Not "telemetry." A disclosure to a third party, which needs an agreement in place first. That reframes the axis.

Langfuse has the most explicit answer: four fully-separated cloud regions — US (Oregon), EU (Ireland), Japan (Tokyo), and a dedicated HIPAA region at hipaa.cloud.langfuse.com — separated down to accounts and infrastructure, so switching regions means a new account and a migration. It will sign a BAA on Pro plan or higher, in the HIPAA region only, via DocuSign, and the docs say the quiet part out loud: do not process PHI in Langfuse until the signed BAA is in place. Around that: SOC 2 Type 2 and ISO 27001 audits, external pen tests, a DPA, and the customer-side controls that matter more than any of it — masking, retention, deletion, region selection, SSO/SCIM, audit logs.

LangSmith is GDPR-compliant, SOC 2 Type 2 certified and HIPAA compliant, with US, EU and APAC cloud instances — and one procurement fact that stops European deals dead: "We do not have a legal entity in the EU that we can contract with today." Also: an org cannot have workspaces in different regions, and cross-region billing is unsupported. Helicone Cloud is SOC2 compliant with EU and US regions, and HIPAA appears at the Team tier, $799 a month — a real number for the table. Phoenix's residency answer is simply "run it yourself": nothing goes to Arize, fully air-gappable; regulated-cloud SKUs live on Arize AX Enterprise.

The FDE instinct to build here: the strongest residency control is the one that reduces what ever reaches the vendor. Mask at the SDK, before the span leaves the process, and every downstream conversation gets easier. That is the same redaction discipline Week 8 will grade you on, arriving a week early in observability clothes.

Axis ⑥ · continuity

Who will own this tool in three years?

The axis engineers skip and control owners never do. You are recommending something the client operates for years; the vendor's trajectory is part of the recommendation.

The clean example is right here. Helicone was acquired by Mintlify on 3 March 2026 and is explicitly in maintenance mode. The founder's post is unambiguous: services stay live "for the foreseeable future in maintenance mode. This means security updates, new models, bug & performance fixes all keep shipping." Read that precisely — a real commitment, and one that contains no new feature investment. For a weekend project, irrelevant. For a SOX-relevant control with a multi-year horizon, it is a strike the memo must name, alongside the scale that made Helicone credible in the first place (14.2 trillion tokens, 16,000 organizations, YC W23).

Continuity risk is not only acquisition. Langfuse v4 is GA with a new observations-first data model, at least a 10× dashboard-load improvement — and trace-level input/output deprecated across the product. That is a migration, and it belongs in "what we're accepting." LangSmith's move to LCU/LSU invalidates older cost models. Phoenix's standalone cloud SKU has been folded into Arize AX tiers. None of that is scandal; all of it is churn, and churn is what your memo has to survive.

So the method matters more than the facts. Check, don't recall. Four places, ten minutes: the licence file in the repository, the release cadence and changelog dates, the pricing page, the vendor blog. A memo that missed Helicone's maintenance mode, Phoenix's ELv2, or LangSmith's mandatory beacon egress was written from training data rather than the web — and those three are exactly the discoveries you should make yourself today.

The protocol

Sixty minutes, in this order

You will not evaluate six axes evenly in an hour, and you shouldn't try. Run them as an elimination order, hardest cut first. One: can trace payloads leave the client's network? That alone usually removes half the field. Two: does counsel need OSI-approved licensing, or is source-available fine? Three: what is the monthly span volume, and what does each meter make that cost? Four, and only then: features. Continuity and residency ride along inside steps one and three.

Two constraints, two different memos — that is the lesson. On the healthcare track the deciding sentence is that intake and ai-summary traces carry PHI, so the spine is BAA-or-air-gap: Phoenix self-hosted if no third party may touch PHI at all, Langfuse's HIPAA region with a signed BAA on Pro-or-higher if managed is acceptable, everything else rejected with a named fact. On the finance track the deciding sentence is that the reconciliation is a SOX-material control, so the spine is retention and continuity: fifteen-day retention disqualifies itself, a vendor in maintenance mode is a disclosure, and "who could view raw payment payloads, and can we prove it?" has a price attached — audit logs and fine-grained RBAC sit behind Langfuse's Enterprise/Teams tiers and LangSmith Enterprise. Same landscape, same hour, different constraint, different answer.

Finish with the line most engineers omit: Reversibility. How would we switch, and what would it cost? If you instrumented with a vendor-neutral SDK behind an OTel Collector, the honest answer is "a Collector config change and a re-ingest of whatever history we care about" — worth more to an exec than any feature you could have compared. Recommending a vendor is easy. Recommending one and proving you're not trapped by it is the job.

FDE mindset

A tool comparison is homework; a memo is a decision someone can sign. Asked "which one should we use?", don't answer with a matrix — answer with the one client constraint that eliminates most of the field, the option it leaves standing, the price at a stated volume, and the exit path if you're wrong. And date every fact: an unstamped price is a guess wearing a suit.

Production code: instrument once, export anywhere

This file names no observability vendor. That is the whole point — the lock-in is the instrumentation SDK, and the backend is a Collector config value.

# Vendor-neutral tracing for the intake summary call. The exporter points at a LOCAL
# OTel Collector, which fans the same span stream out to Langfuse / Phoenix / LangSmith.
# Auth: Bedrock API key in AWS_BEARER_TOKEN_BEDROCK (boto3 reads it; no IAM role).
import boto3
from opentelemetry import trace
from opentelemetry.sdk.trace import TracerProvider
from opentelemetry.sdk.trace.export import BatchSpanProcessor
from opentelemetry.exporter.otlp.proto.http.trace_exporter import OTLPSpanExporter

# HTTP, not gRPC: Langfuse accepts HTTP/JSON + HTTP/protobuf only.
provider = TracerProvider()
provider.add_span_processor(BatchSpanProcessor(OTLPSpanExporter()))
trace.set_tracer_provider(provider)
tracer = trace.get_tracer("intake.summary")

bedrock = boto3.client("bedrock-runtime", region_name="us-east-1")
MODEL = "us.anthropic.claude-haiku-4-5-20251001-v1:0"

def summarize(note: str) -> str:
    with tracer.start_as_current_span("llm.summarize") as span:
        span.set_attribute("gen_ai.system", "aws.bedrock")      # OTel GenAI semconv
        span.set_attribute("gen_ai.request.model", MODEL)        # (still pre-stable)
        span.set_attribute("openinference.span.kind", "LLM")    # OpenInference, Apache 2.0
        r = bedrock.converse(
            modelId=MODEL,
            messages=[{"role": "user", "content": [{"text": note}]}],
            inferenceConfig={"maxTokens": 400, "temperature": 0},
        )
        # Metadata only -- the note is PHI, so no prompt/completion payload on the span.
        span.set_attribute("gen_ai.usage.input_tokens", r["usage"]["inputTokens"])
        span.set_attribute("gen_ai.usage.output_tokens", r["usage"]["outputTokens"])
        return r["output"]["message"]["content"][0]["text"]

Nothing here is vendor-specific except the exporter's endpoint environment variable — which is why the memo's Reversibility line can honestly say "a Collector config change."
