Ask a model about the briefs

Every issue is also stored as data in this repository, so a model can answer your questions from the newest sourced items instead of from its own, possibly outdated, training data.

  1. Search the archive. From a clone of this repository, run the query script with your question. It needs only Python 3, no packages and no API key. 
    python3 brief-pipeline/scripts/query.py "What compliance deadlines should a hiring-screening demo plan for?" --k 3
  2. Give the model the rules. Use answer-from-briefs.md as the system prompt. Paste the script's output under RETRIEVED CONTEXT, then your question.
  3. Read the flags. The model cites items as [1], [2]. It says so when an item needs a recheck, comes only from a secondary source, has a deadline that has passed, or was replaced by a later week. When nothing matches, it says the archive doesn't cover the question yet rather than guessing.

Useful filters: --section dev|practice|compliance, --since 2026-11-01, --tag mcp, and --format json for your own agent.

Use it from your own agent

  • One static file. The search index is served with this site at brief-pipeline/data/index.json. It carries precomputed keyword statistics, so a browser page or an agent tool can rank items without a server.
  • A fixed shape. Each weekly file follows the brief item schema: section, badge, dates, primary or secondary sources, tags, and a topic key that links a story across weeks.
  • Freshness is part of the answer. Compliance items read more than 30 days ago, tool items more than 60 and practice items more than 90 are flagged for a recheck against the source.

How it works and how to add a week: brief-pipeline/README.md.

Compliance items are training material, not legal advice. Vendor benchmark numbers are the vendor's own unless an item says otherwise.
