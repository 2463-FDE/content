# w04d3 — Alt research: CrewAI & AutoGen vs LangGraph (multi-agent)

W4 is the LangGraph multi-agent week; this alt-research day compares how CrewAI and AutoGen (now Microsoft Agent Framework) do multi-agent orchestration against our LangGraph pick. Scope: multi-agent mechanics and selection tradeoffs only — d1 covers orchestration patterns generically, d2 covers LangGraph state/checkpointers, d4-d5 cover Neo4j/GraphRAG. w03d3 already covered the broad framework landscape; this day goes deeper on the multi-agent layer specifically. Every claim is source-backed and URL-verified 2026-07.

version-stamps:
  - LangGraph: 1.2.7, released 2026-06-30, Python >=3.10 (verified 2026-07 via PyPI) — self-described "low-level orchestration framework for building, managing, and deploying long-running, stateful agents"; durable execution + persistence + HITL
  - langgraph-supervisor-py / langgraph-swarm-py: official prebuilt multi-agent libraries; swarm latest release 0.1.0 (2025-12-04); supervisor maintainers now recommend building the supervisor pattern directly via tools for most cases (verified 2026-07)
  - CrewAI: 1.15.1, released 2026-06-27, Python >=3.10,<3.14 (verified 2026-07 via PyPI) — standalone, "completely independent of LangChain"; multi-agent = Crews with Process.sequential / Process.hierarchical + delegation tools
  - Microsoft Agent Framework: `agent-framework` 1.10.0, released 2026-06-30, Python >=3.10 (verified 2026-07 via PyPI) — the successor to AutoGen (+ Semantic Kernel); ships 5 built-in orchestrations: sequential, concurrent, handoff, group chat, magentic
  - AutoGen: legacy/migration-source only; Microsoft's migration guide (dated 2026-04-01, updated 2026-06-26) maps AutoGen GroupChat/teams onto Agent Framework Workflows

STALE-ADVICE WARNING for authoring: pre-2026 models will present "AutoGen GroupChat" as Microsoft's live multi-agent answer and CrewAI as a LangChain wrapper. Both are wrong. AutoGen is a legacy migration source — its GroupChat/Magentic-One ideas now live in Microsoft Agent Framework's workflow orchestrations — and CrewAI is standalone, built from scratch, independent of LangChain. Also stale: describing LangGraph multi-agent as "just draw a graph" — current docs push five named patterns (subagents, handoffs, skills, router, custom workflow) with context engineering as the central design concern, and steer most handoff cases to a single agent with middleware rather than multi-subgraph builds. Do not seed the day from pre-2026 memory.

## Claims (each MUST carry a source)

### LangGraph (our pick)

- LangGraph 1.2.7 (released 2026-06-30) describes itself as "a low-level orchestration framework for building, managing, and deploying long-running, stateful agents," emphasizing durable execution, streaming, human-in-the-loop, and persistence — the substrate the multi-agent patterns compile down to. — [langgraph — PyPI](https://pypi.org/project/langgraph/)
- Current LangChain/LangGraph docs frame multi-agent as five patterns — subagents (main agent calls subagents as tools), handoffs (agents transfer control via tool calls), skills (one agent loads specialized prompts on demand), router (classify then dispatch), and custom LangGraph workflows — and state that "at the center of multi-agent design is context engineering — deciding what information each agent sees." — [Multi-agent — Docs by LangChain](https://docs.langchain.com/oss/python/langchain/multi-agent)
- LangGraph handoffs are implemented as tools that return a `Command` object combining state update + control flow; with agents-as-subgraphs, `Command(goto=..., graph=Command.PARENT)` navigates to a sibling agent node in the parent graph, and you must return a `ToolMessage` with the matching `tool_call_id` or the conversation history becomes malformed. — [Handoffs — Docs by LangChain](https://docs.langchain.com/oss/python/langchain/multi-agent/handoffs)
- The docs' explicit recommendation: "Use single agent with middleware for most handoffs use cases — it's simpler. Only use multiple agent subgraphs when you need bespoke agent implementations" (e.g., a node that is itself a complex graph with reflection or retrieval). — [Handoffs — Docs by LangChain](https://docs.langchain.com/oss/python/langchain/multi-agent/handoffs)
- `langgraph-supervisor-py` packages the hierarchical pattern — `create_supervisor([agent1, agent2], model=model)` builds a central supervisor that delegates via tool-based handoffs — but its maintainers now recommend "using the supervisor pattern directly via tools rather than this library for most use cases." — [langgraph-supervisor-py — GitHub](https://github.com/langchain-ai/langgraph-supervisor-py)
- `langgraph-swarm-py` packages the peer-to-peer pattern: "agents dynamically hand off control to one another based on their specializations," and an `active_agent` state variable persisted via checkpointer means "on subsequent interactions, the conversation resumes with that agent" (latest release 0.1.0, 2025-12-04). — [langgraph-swarm-py — GitHub](https://github.com/langchain-ai/langgraph-swarm-py)

### CrewAI

- CrewAI 1.15.1 (released 2026-06-27, Python >=3.10,<3.14) is "built entirely from scratch — completely independent of LangChain or other agent frameworks"; its multi-agent unit is the Crew (role-based agent team), with Flows for deterministic event-driven control. — [crewai — PyPI](https://pypi.org/project/crewai/)
- CrewAI's multi-agent coordination is chosen via a `Process` enum with exactly two implementations: sequential ("task execution follows the predefined order in the task list, with the output of one task serving as context for the next") and hierarchical, where "the manager allocates tasks to agents based on their capabilities, reviews outputs, and assesses task completion" — tasks are not pre-assigned but dynamically delegated. — [Processes — CrewAI Docs](https://docs.crewai.com/en/concepts/processes)
- Hierarchical mode requires either `manager_llm` (CrewAI auto-creates the manager agent) or a custom `manager_agent`; the manager "coordinates the workflow, delegates tasks, and validates outcomes." This is prompt-driven manager routing, not an explicit graph — the contrast with LangGraph's node/edge control. — [Hierarchical Process — CrewAI Docs](https://docs.crewai.com/en/learn/hierarchical-process)
- Peer collaboration in CrewAI is a flag, not a graph: setting `allow_delegation=True` automatically injects two tools — `Delegate work to coworker(task, context, coworker)` and `Ask question to coworker(question, context, coworker)` — so any agent can hand work sideways; docs recommend enabling it for coordinators/generalists and disabling it for focused specialists. — [Collaboration — CrewAI Docs](https://docs.crewai.com/en/concepts/collaboration)

### AutoGen → Microsoft Agent Framework

- Microsoft's own framing: AutoGen "started as a research project at Microsoft Research and pioneered several concepts in multi-agent orchestration, such as GroupChat and event-driven agent runtime," while Agent Framework — built by the core AutoGen and Semantic Kernel teams — "is designed to be a new foundation for building AI applications going forward." The migration guide (dated 2026-04-01) maps AutoGen's `RoundRobinGroupChat` and `GraphFlow` onto Agent Framework Workflows, with Swarm and `SelectorGroupChat` listed as roadmap items still in development. — [AutoGen to Microsoft Agent Framework Migration Guide — Microsoft Learn](https://learn.microsoft.com/en-us/agent-framework/migration-guide/from-autogen/)
- The migration guide also concedes a gap LangGraph had first: "AutoGen's `Team` abstraction runs continuously once started and doesn't provide built-in mechanisms to pause execution for human input" — Agent Framework closes it with a workflow-level request/response API (`ctx.request_info()` + `@response_handler`). — [AutoGen to Microsoft Agent Framework Migration Guide — Microsoft Learn](https://learn.microsoft.com/en-us/agent-framework/migration-guide/from-autogen/)
- Agent Framework ships five built-in multi-agent orchestrations — Sequential, Concurrent, Handoff ("agents transfer control to each other based on context"), Group Chat ("agents collaborate in a shared conversation"), and Magentic ("a manager agent dynamically coordinates specialized agents") — all supporting human-in-the-loop via tool approval and request info. — [Workflow orchestrations in Agent Framework — Microsoft Learn](https://learn.microsoft.com/en-us/agent-framework/workflows/orchestrations/)
- Magentic orchestration "is designed based on the Magentic-One system invented by AutoGen": a Magentic manager plans, selects the next agent per round, maintains a progress ledger (request satisfied? in a loop? progress being made? next speaker?), and auto-replans on stall detection, with configurable `max_round_count` / `max_stall_count` / `max_reset_count` and optional human plan review. — [Magentic orchestration — Microsoft Learn](https://learn.microsoft.com/en-us/agent-framework/workflows/orchestrations/magentic)
- The primary paper behind that pattern: Magentic-One (Microsoft, Nov 2024) is a generalist multi-agent system whose Orchestrator "plans, tracks progress, and re-plans to recover from errors" using task and progress ledgers, achieving "statistically competitive performance to the state-of-the-art" on GAIA, AssistantBench, and WebArena. — [Magentic-One: A Generalist Multi-Agent System for Solving Complex Tasks — arXiv](https://arxiv.org/abs/2411.04468)
- The pip package is `agent-framework` 1.10.0 (released 2026-06-30, Python >=3.10, Development Status 5 production/stable), bundling agents, tools, and the multi-agent orchestration patterns. — [agent-framework — PyPI](https://pypi.org/project/agent-framework/)

### Comparison spine (for authoring)

- Control model: LangGraph exposes the graph itself (nodes, edges, `Command` handoffs, subgraphs) so orchestration is explicit code; CrewAI hides orchestration behind a `Process` enum plus an LLM manager and delegation tools; Agent Framework packages named orchestration patterns (sequential/concurrent/handoff/group-chat/magentic) as prebuilt workflows. Sources: [LangChain handoffs docs](https://docs.langchain.com/oss/python/langchain/multi-agent/handoffs), [CrewAI processes](https://docs.crewai.com/en/concepts/processes), [Agent Framework orchestrations](https://learn.microsoft.com/en-us/agent-framework/workflows/orchestrations/).
- All three converge on the same two archetypes taught on d1: a central coordinator (LangGraph supervisor / CrewAI hierarchical manager / MAF group-chat+magentic manager) vs peer handoffs (LangGraph swarm / CrewAI delegation tools / MAF handoff orchestration) — the differentiator is how much of the routing is explicit graph vs LLM judgment. Sources: [langgraph-supervisor-py](https://github.com/langchain-ai/langgraph-supervisor-py), [langgraph-swarm-py](https://github.com/langchain-ai/langgraph-swarm-py), [CrewAI hierarchical process](https://docs.crewai.com/en/learn/hierarchical-process), [MAF orchestrations](https://learn.microsoft.com/en-us/agent-framework/workflows/orchestrations/).

## Concept IDs (interview question-bank seeds)

Each id carries a one-line definition so the question-bank author seeds from a fixed meaning, not from prose.

- langgraph-command-handoffs — LangGraph's multi-agent handoff mechanism: a tool returns a `Command` that combines a state update with control flow (`goto` + `graph=Command.PARENT` to jump to a sibling agent subgraph), requiring a paired `ToolMessage` to keep history well-formed; docs recommend single-agent-with-middleware for most handoff cases and reserve multi-subgraph builds for bespoke agents.
- supervisor-vs-swarm — the two LangGraph multi-agent archetypes as shipped libraries: supervisor (central agent delegates via tool-based handoffs, `create_supervisor`; maintainers now favor building the pattern directly) vs swarm (peers hand off dynamically by specialization, with a checkpointed `active_agent` so conversations resume with the last-active agent).
- crewai-hierarchical-process — CrewAI's manager-based multi-agent mode: `Process.hierarchical` plus `manager_llm` (auto-created manager) or a custom `manager_agent`, where the manager dynamically allocates tasks, reviews outputs, and validates completion — LLM-judgment routing, versus the default `Process.sequential` task chain.
- crewai-delegation-tools — CrewAI's peer-collaboration mechanism: `allow_delegation=True` auto-injects `Delegate work to coworker` and `Ask question to coworker` tools so agents hand work sideways without any graph; recommended on for coordinators/generalists, off for focused specialists.
- magentic-orchestration — the Magentic-One-derived pattern (arXiv 2411.04468) now shipped in Microsoft Agent Framework: a manager plans, keeps task + progress ledgers (satisfied / in-loop / progressing / next speaker), auto-replans on stall detection with round/stall/reset limits, and optionally pauses for human plan review.
- multi-agent-framework-tradeoffs — the CrewAI/AutoGen-vs-LangGraph decision axes: explicit graph control (LangGraph nodes/Command) vs LLM-manager routing (CrewAI hierarchical) vs prebuilt orchestration patterns (Agent Framework's sequential/concurrent/handoff/group-chat/magentic), plus AutoGen's legacy status and where durable execution and human-in-the-loop live in each stack.
