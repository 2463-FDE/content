## Concept IDs

These seed the interview question bank. Each is addressable by ID.

- `faithfulness` — Generation-side metric: fraction of a response's claims that are
  supported by the retrieved context (supported claims / total claims, 0–1). Detects
  hallucination / ungrounded generation.
- `context-precision` — Retrieval-side metric: are the relevant chunks ranked at the
  top? Mean precision@k over retrieved chunks; rank position of irrelevant chunks
  matters.
- `context-recall` — Retrieval-side metric: was all the needed information actually
  retrieved? Fraction of reference-answer claims attributable to the retrieved context.
- `noise-sensitivity` — Robustness metric: how often the system produces incorrect
  claims when given relevant or irrelevant retrieved documents (incorrect claims /
  total claims; lower is better).
- `seven-failure-points` — The canonical RAG failure-mode taxonomy (FP1 Missing
  Content … FP7 Incomplete) from the arXiv experience report; separates retrieval-side
  failures (FP1/FP2) from generation-side extraction failures (FP4).
- `llm-as-judge-eval` — The shared mechanism behind faithfulness/recall/precision:
  claims are extracted and verified by an LLM (or, for faithfulness, a cheaper NLI
  classifier like Vectara HHEM-2.1-Open) rather than by exact string match.

## Claims (each MUST carry a source)

- The canonical Ragas repository is now hosted under the `vibrantlabsai` GitHub org (`github.com/vibrantlabsai/ragas`); the PyPI package name remains `ragas` and its project links point to that repo. — [ragas · PyPI](https://pypi.org/project/ragas/)

- The three core RAG metrics — context precision, context recall, and faithfulness — map to the three things a RAG system must get right: rank useful chunks high, retrieve all needed chunks, and ground the answer in those chunks. — [List of available metrics - Ragas](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/)
- Faithfulness measures how factually consistent a response is with the retrieved context on a 0–1 scale, computed as (number of supported claims) / (total claims in response): claims are extracted from the response, then each is verified against the retrieved context. — [Faithfulness - Ragas](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/faithfulness/)
- Ragas offers a `FaithfulnesswithHHEM` variant that uses Vectara's HHEM-2.1-Open T5-based classifier to perform the claim-verification step more cheaply than per-claim LLM calls. — [Faithfulness - Ragas](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/faithfulness/)
- DeepEval computes faithfulness the same way (truthful claims / total claims, a claim is truthful if it does not contradict the retrieval_context), requires `input` + `actual_output` + `retrieval_context`, and uses a default pass threshold of 0.5 (with `strict_mode` forcing binary scoring at threshold 1). — [Faithfulness | DeepEval](https://deepeval.com/docs/metrics-faithfulness)
- Context Precision measures whether relevant chunks are ranked at the top, computed as mean precision@k across retrieved chunks (precision@k = true positives@k / (true positives@k + false positives@k)); the position of an irrelevant chunk matters — an irrelevant chunk ranked first hurts the score far more than one ranked lower. — [Context Precision - Ragas](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/context_precision/)
- Context Precision has reference-based (`LLMContextPrecisionWithReference`), reference-free (`LLMContextPrecisionWithoutReference`, compares chunks to the response), and non-LLM (`IDBasedContextPrecision`) variants. — [Context Precision - Ragas](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/context_precision/)
- Context Recall measures whether all needed information was retrieved, computed as (reference claims supported by retrieved context) / (total claims in the reference); the reference/ground-truth answer is broken into claims and each is checked for attribution to the retrieved context. — [Context Recall - Ragas](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/context_recall/)
- Noise Sensitivity measures how often the system makes errors when given relevant or irrelevant retrieved documents, computed as (incorrect claims) / (total claims in the response); lower is better. — [Noise Sensitivity - Ragas](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/noise_sensitivity/)
- The "Seven Failure Points" experience report identifies the canonical RAG failure modes: FP1 Missing Content, FP2 Missed the Top Ranked Documents, FP3 Not in Context (consolidation/context-window limits), FP4 Not Extracted, FP5 Wrong Format, FP6 Incorrect Specificity, FP7 Incomplete. — [Seven Failure Points When Engineering a RAG System (arXiv:2401.05856)](https://arxiv.org/html/2401.05856v1)
- Faithfulness and context recall are the highest-signal metrics for most production systems: faithfulness catches hallucination (the most dangerous failure mode) and context recall tells you whether the retrieval architecture is fundamentally sound. — [List of available metrics - Ragas](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/)
- The faithfulness failure mode (FP4 Not Extracted) is distinct from a retrieval failure (FP1/FP2): the answer is present in the context but the LLM fails to extract it — which is why generation-side and retrieval-side metrics must be reported separately. — [Seven Failure Points When Engineering a RAG System (arXiv:2401.05856)](https://arxiv.org/html/2401.05856v1)
