## Claims

### The currency traps — say these out loud, students will get them wrong from memory

- **Helicone was acquired by Mintlify on 2026-03-03 and is in maintenance mode.** The founder's post is unambiguous: "Helicone has been acquired by Mintlify… Helicone's services will remain live for the foreseeable future in maintenance mode. This means security updates, new models, bug & performance fixes all keep shipping." No new feature investment is promised. Historical scale for context: 14.2 trillion tokens processed, 16,000 organizations, YC W23. — [Helicone is joining Mintlify](https://www.helicone.ai/blog/joining-mintlify)
- **Arize Phoenix is Elastic License 2.0, not Apache 2.0.** The repo states: "This software is licensed under the terms of the Elastic License 2.0 (ELv2)," alongside a patent notice ("Portions of this code are patent protected by one or more U.S. Patents"). ELv2 is source-available, **not OSI-approved**. Nearly every model answers "Apache 2.0" here. — [Arize-ai/phoenix — GitHub](https://github.com/Arize-ai/phoenix)
- **LangSmith repriced onto normalized units.** Pricing is now LCU ("a normalized unit of work done on the LangSmith Platform… 1 LCU = $1.50") and LSU ("a normalized unit of data stored or managed… 1 LSU = $1.00"). Plus is $39/seat/mo including 10k base traces, then **0.005 LSU per additional trace**; Developer is $0/seat with 5k base traces. Flat per-trace pricing from older answers is stale. — [LangSmith plans and pricing](https://www.langchain.com/pricing-langsmith)
- **"Phoenix Cloud" as a standalone SKU is gone from the pricing page.** `phoenix.arize.com/pricing` now serves **Arize AX** tiers: AX Free (25k spans/mo, 1 GB ingest, 15-day retention, unlimited users and evals), AX Pro **$50/mo** (50k spans, 10 GB, 30-day retention), AX Enterprise (custom, "SaaS or Self-Hosted"). Phoenix-the-OSS-project remains free to self-host. — [Arize AX pricing](https://phoenix.arize.com/pricing)
- **Langfuse v4 is out** and changes the data model: "an observations-first data model… Every operation is now a first-class queryable object," GA on Cloud and self-hosted, with "at least 10x" dashboard load improvement for large projects. **Trace-level input/output is deprecated across the product.** — [Langfuse v4 is live](https://langfuse.com/docs/v4)

### Deployment model — the axis that eliminates options fastest

- **Langfuse self-hosted is the same codebase as Cloud**, deployable via Docker Compose (low-scale), Kubernetes/Helm, or Terraform for AWS/Azure/GCP, and "can be deployed within a VPC or on-premises in high-security environments. Internet access is optional." — [Self-host Langfuse](https://langfuse.com/self-hosting)
- **Langfuse's real self-host bill is five components, not one container**: Langfuse Web + Langfuse Worker, plus **Postgres (OLTP), ClickHouse (OLAP), Redis/Valkey (queue + cache), and S3/blob storage**. Hard constraint: "All infrastructure components (ClickHouse and Postgres) **must** run with their timezone set to UTC. Non-UTC timezones will cause queries to return incorrect or empty results." — [Self-host Langfuse](https://langfuse.com/self-hosting)
- **Phoenix self-hosting is the most permissive**: "free to self-host with no feature limitations. Your data stays entirely within your infrastructure—nothing is sent to Arize and can be fully air-gapped." Deployment targets: CLI, Docker/Compose, Kubernetes, Helm, AWS CloudFormation, Railway, Render, Google Cloud Run, Azure ARM. Auth includes OAuth2, LDAP, and local accounts; RBAC and retention policies are in the free product. — [Phoenix Self-Hosting](https://arize.com/docs/phoenix/self-hosting)
- **Self-hosted LangSmith is Enterprise-only and is not air-gapped by default.** Enterprise is the only plan with "self-hosted and hybrid deployment options." The install docs say "Ensure egress to `https://beacon.langchain.com` is available," and the egress page states that requirement covers **billing telemetry (license verification + subscription/usage reporting) which "cannot be disabled."** Running with no egress requires a separately negotiated "offline (air-gapped) license" from the account team. Enabling Engine adds a **second egress destination** through which "Engine content leaves your environment." — [LangSmith self-host egress](https://docs.langchain.com/langsmith/self-host-egress) · [Deploy self-hosted full platform](https://docs.langchain.com/langsmith/deploy-self-hosted-full-platform)
- **Hybrid is a real third option, not marketing.** LangSmith Enterprise offers "Hybrid: SaaS control plane, Self-hosted data plane," vs Cloud ("Fully managed by LangChain") and Self-Hosted ("Fully self-managed"; data location "Your VPC"). — [LangSmith plans and pricing](https://www.langchain.com/pricing-langsmith)
- **Helicone self-hosts four ways** — manual install, Docker Compose, Kubernetes, and cloud deployment (AWS/GCP/Azure) — with support "through our Discord community" for the OSS path. — [Self-Hosting Helicone](https://docs.helicone.ai/getting-started/self-host/overview)

### Data residency and regulated-data posture

- **Langfuse has four fully-separated Cloud regions**: US (Oregon, AWS `us-west-2`), EU (Ireland, `eu-west-1`), Japan (Tokyo, `ap-northeast-1`), and a dedicated **HIPAA region** (`hipaa.cloud.langfuse.com`, Oregon). "All data, user accounts, and infrastructure are completely separated between the regions" — switching regions means a new account plus a data migration. — [Langfuse data regions](https://langfuse.com/security/data-regions)
- **Langfuse will sign a BAA**, on Pro plan or higher, in the HIPAA region only, executed via DocuSign — and the docs are explicit: "Do not process PHI in Langfuse until the signed BAA is in place." — [Langfuse HIPAA](https://langfuse.com/security/hipaa)
- **Langfuse compliance posture**: annual SOC 2 Type 2 and ISO 27001 audits plus external penetration tests, DPA available, GDPR page, plus customer-side controls — **masking**, data retention, data deletion, region selection, SSO/SCIM, audit logs. — [Langfuse security overview](https://langfuse.com/security)
- **LangSmith**: "complies with the General Data Protection Regulation (GDPR)… We are also SOC 2 Type 2 certified and are HIPAA compliant," with US and EU cloud instances (endpoints `eu.api.smith.langchain.com`, `apac.api.smith.langchain.com`, `aws.api.smith.langchain.com`). **Procurement catch: "We do not have a legal entity in the EU that we can contract with today."** Also: an org cannot have workspaces in different regions, and cross-region billing is unsupported. — [LangSmith regions FAQ](https://docs.langchain.com/langsmith/regions-faq)
- **Helicone Cloud** is SOC2 compliant with a choice of "EU and US regions to meet your data residency and compliance requirements"; HIPAA compliance appears at the **Team plan ($799/mo)**. — [Helicone data security & privacy](https://docs.helicone.ai/references/data-autonomy) · [Helicone pricing](https://www.helicone.ai/pricing)
- **Phoenix's residency answer is "run it yourself."** The self-hosting page's pitch is exactly that: nothing sent to Arize, fully air-gappable. Regulated-cloud SKUs live on the Arize AX Enterprise tier (the AX pricing table lists SOC 2 Type II, HIPAA, and Data region as enterprise-tier rows). — [Phoenix Self-Hosting](https://arize.com/docs/phoenix/self-hosting) · [Arize AX pricing](https://phoenix.arize.com/pricing)

### Pricing meters — four incompatible units, which is the point

- **Langfuse Cloud** meters "units": Hobby free (50k units/mo, 30-day data access, 2 users); Core $29/mo (100k units, 90 days, unlimited users); Pro $199/mo (100k units, **3 years** data access, retention management, SOC2/ISO27001 reports, HIPAA-ready region); Enterprise $2,499/mo (audit logs, SCIM API, custom rate limits). Overage is **$8/100k units**, lower with volume. Teams add-on $300/mo adds enterprise SSO, SSO enforcement, and fine-grained RBAC. — [Langfuse pricing](https://langfuse.com/pricing)
- **Langfuse self-hosted OSS is free with "Unlimited units / usage"** and — notably — **includes Enterprise SSO and RBAC**. Self-Hosted Enterprise (custom pricing) adds management APIs, project-level RBAC, data retention policies, and audit logs, and is "bundled with ClickHouse Cloud, ClickHouse BYOC, or ClickHouse Private" with "Langfuse pricing… additive to your ClickHouse commercial plan." — [Langfuse self-hosted pricing](https://langfuse.com/pricing-self-host)
- **Helicone** meters requests + storage: Hobby free (10,000 requests, 1 GB, 1 seat, 1 org); Pro $79/mo (unlimited seats, alerts & reports, HQL query language, usage-based on top); Team $799/mo (5 orgs, **SOC-2 & HIPAA compliance**, dedicated Slack); Enterprise (custom MSA, SAML SSO, on-prem). All paid tiers include 10k free requests then usage-based. — [Helicone pricing](https://www.helicone.ai/pricing)
- **Arize AX** meters spans + ingest GB + retention window (Free 25k/1 GB/15 days; Pro $50/mo 50k/10 GB/30 days), with unlimited users and unlimited evals on every tier. — [Arize AX pricing](https://phoenix.arize.com/pricing)
- **Teaching point for the memo:** you cannot compare these prices without a workload. A "unit," a "request," a "span," and an "LSU" are four different things, and a trace fans out into many spans. The memo's cost section must state the assumed monthly volume and the fan-out ratio, or it is not a cost estimate.

### OTel-native vs proprietary — "we support OpenTelemetry" tells you nothing

- **All four ingest OTLP.** The real question is whether the vendor's *internal* model is OTel's or whether OTLP is a translation layer. — synthesis across the four vendor docs below.
- **Phoenix is the most OTel-native**: "built on top of OpenTelemetry and… powered by [OpenInference] instrumentation," accepting traces over OTLP with auto-instrumentation for LlamaIndex, LangChain, DSPy, Mastra, Vercel AI SDK, OpenAI, Bedrock, Anthropic, across Python, TypeScript, and Java. — [What is Arize Phoenix?](https://arize.com/docs/phoenix) · [Phoenix tracing overview](https://arize.com/docs/phoenix/tracing/llm-traces)
- **Langfuse is an OTel *backend* with a mapping layer.** It receives OTLP at `/api/public/otel`; it "supports OTLP over HTTP with both `HTTP/JSON` and `HTTP/protobuf`. **`gRPC` is not supported yet.**" And it says why the mapping exists: "As the Semantic Conventions for GenAI attributes on traces are still evolving, Langfuse maps the received OTel traces to the Langfuse data model." v4 gotcha: direct OTLP sends need `x-langfuse-ingestion-version: 4` or "data can be delayed by up to 10 minutes." — [Langfuse OpenTelemetry integration](https://langfuse.com/integrations/native/opentelemetry)
- **LangSmith is proprietary-model-first with a documented translation table**: `gen_ai.system` → `metadata.ls_provider`, `gen_ai.operation.name` → run type, `gen_ai.prompt` → `inputs`, `gen_ai.completion` → `outputs`, `gen_ai.tool.name` → sets run type to "tool". It also documents the Collector **fanout** pattern — one span stream routed to multiple backends simultaneously — which is the escape hatch that makes a vendor swap cheap. — [Trace with OpenTelemetry — LangSmith](https://docs.langchain.com/langsmith/trace-with-opentelemetry)
- **Helicone is architecturally different: it's a gateway, not an instrumentation library.** Point the OpenAI SDK at `https://ai-gateway.helicone.ai` and logging is automatic across "100+ LLM models," with credits at "0% markup," automatic provider fallbacks, and BYO provider keys as an option. Zero-code capture — but it only ever sees what crosses the proxy, so retrieval steps, tool calls, and agent control flow are invisible unless you add tracing anyway. — [Helicone quickstart](https://docs.helicone.ai/getting-started/quick-start)
- **Two rival convention sets sit under the "OTel-native" claim.** **OpenInference** (Arize, Apache 2.0) is "designed to provide insight into the invocation of LLMs and the surrounding application context such as retrieval from vector stores and the usage of external tools," and is "transport and file-format agnostic." **OpenLLMetry** (Traceloop, Apache 2.0) ships "standard OpenTelemetry instrumentations for LLM providers and Vector DBs" and notes its semantic conventions "are now part of OpenTelemetry." — [OpenInference](https://github.com/Arize-ai/openinference) · [OpenLLMetry](https://github.com/traceloop/openllmetry)
- **The standard they're all converging on is not finished.** The OTel GenAI semantic conventions moved into `open-telemetry/semantic-conventions-genai` ("Semantic Conventions for Generative AI (GenAI), including spans, metrics, and events for GenAI clients, MCP… and provider-specific conventions"), and the README's Schema URL section reads simply "TODO," with no releases cut. Portability across these four vendors is aspirational today. — [open-telemetry/semantic-conventions-genai](https://github.com/open-telemetry/semantic-conventions-genai) · [Moved: Generative AI semantic conventions](https://opentelemetry.io/docs/specs/semconv/gen-ai/)
- **Consequence to teach:** instrument with a vendor-neutral library (OpenInference or OpenLLMetry) and export through an OTel Collector. The lock-in decision is the *instrumentation SDK*, not the backend. A Collector with fanout makes "try two vendors for a month" a config change.

### License tiers — four legally different meanings of "open source"

- **Langfuse: MIT, except `ee/`.** "This repository is MIT licensed, except for the `ee` folders." The self-hosted OSS tier is explicitly "MIT License… All core platform features and APIs… Enterprise SSO and RBAC… Unlimited units / usage." — [langfuse/langfuse](https://github.com/langfuse/langfuse) · [Langfuse self-hosted pricing](https://langfuse.com/pricing-self-host)
- **Helicone: Apache 2.0**, with the vendor's stated rationale including "Preventing Vendor Lock-In: We believe users should have the freedom to modify and control the software they rely on." — [Helicone open source](https://docs.helicone.ai/references/open-source) · [Helicone/helicone](https://github.com/Helicone/helicone)
- **Phoenix: Elastic License 2.0** — source-available. ELv2 forbids providing the software to third parties as a managed service and forbids circumventing license-key functionality. That is *irrelevant* for internal client use and *disqualifying* if the deliverable is a hosted offering resold to the client's own customers. Both facts belong in the memo. — [Arize-ai/phoenix](https://github.com/Arize-ai/phoenix)
- **LangSmith: proprietary**, self-host gated to Enterprise with a license key verified over the network. — [LangSmith plans and pricing](https://www.langchain.com/pricing-langsmith) · [LangSmith self-host egress](https://docs.langchain.com/langsmith/self-host-egress)

### What each is actually best at (the honest one-liners)

- **LangSmith** — best when the app is LangChain/LangGraph and the team wants zero-friction depth: set `LANGSMITH_OTEL_ENABLED=true` and traces appear, plus evals, datasets, prompt management, deployments, and Engine in one platform. Weakest on residency (no EU contracting entity) and on air-gap (beacon egress required). — [Trace with OpenTelemetry](https://docs.langchain.com/langsmith/trace-with-opentelemetry) · [LangSmith regions FAQ](https://docs.langchain.com/langsmith/regions-faq)
- **Langfuse** — best when you need a *credible self-host story with a paid escape hatch*: MIT core, unlimited self-hosted usage including SSO/RBAC, same codebase as Cloud, four Cloud regions including a HIPAA region with a signable BAA. Cost: five infra components to operate. — [Langfuse self-hosted pricing](https://langfuse.com/pricing-self-host) · [Self-host Langfuse](https://langfuse.com/self-hosting)
- **Arize Phoenix** — best when the work is *evaluation and experimentation on traces* and the data cannot leave the building: free, no feature gates, air-gappable, OTel/OpenInference-native, unlimited evals even on the free hosted tier. Cost: ELv2, and the enterprise/support path routes you to Arize AX. — [Phoenix Self-Hosting](https://arize.com/docs/phoenix/self-hosting) · [What is Arize Phoenix?](https://arize.com/docs/phoenix)
- **Helicone** — best (historically) for *fastest possible time-to-first-trace* on a plain LLM app: change one base URL and you have logging, caching, and fallbacks. Today the acquisition changes the recommendation: for a client system with a multi-year horizon, "maintenance mode" is a strike that the memo must name. — [Helicone quickstart](https://docs.helicone.ai/getting-started/quick-start) · [Helicone is joining Mintlify](https://www.helicone.ai/blog/joining-mintlify)

### Teaching angle — running the 60-minute decision protocol

- The exercise is *not* "pick the best tool." It is: produce a memo with **three to four options, one recommendation, and the single client constraint that decided it.** Everything above is input; the memo's spine is one constraint.
- **The elimination order that works in 60 minutes:** (1) Can trace payloads leave the client's network? — that alone cuts the field. (2) Does the client's counsel need OSI-approved licensing or is source-available fine? (3) What is the monthly span volume and what does each meter make that cost? (4) Only then, features.
- **Force students to verify, not recall.** Three planted discoveries they should find themselves: Helicone's maintenance mode, Phoenix's ELv2, and LangSmith's mandatory beacon egress. Any memo that misses all three was written from training data.
- **The exec-signable memo shape:** one-page — Decision, Options considered (with the disqualifying fact for each rejected one), Recommendation, The constraint that decided it, Cost at assumed volume, Reversibility (how we'd switch), and What we're accepting. The reversibility line is where OTel Collector fanout earns its place.
- **Cost honesty rule:** every price in the memo carries a workload assumption and a verified date. Prices in this brief are stamped 2026-08-06; a memo that reuses them in three months without re-verification is the failure mode the day is teaching against.

## Client hook

### Healthcare — *"The portal is flaky and I'm always the last to know. Give me visibility — and make sure that AI summary thing can't say anything crazy."*

Week 7 asks for structured tracing on the intake path, a golden-signals dashboard spec, one working alert, and a guardrail on the LLM summary. **This day answers the question the client will ask the moment they see the tracing plan: "where does that trace data go?"** The intake/eligibility path and the `ai-summary` endpoint both carry PHI — transcripts, medications, encounter content — so a trace payload *is* a PHI disclosure. That is the single constraint that decides this memo.

Concretely, this day's landscape supplies:
- The **BAA line**, which is the week-8 problem arriving early (the packet's hidden problem there is "PHI to an LLM vendor with no BAA"). Sending traces to a SaaS observability vendor without a BAA repeats the exact mistake the students are about to be graded on. Langfuse's HIPAA region + DocuSign BAA (Pro plan or higher) and Helicone's Team-tier HIPAA are the concrete "yes we can" answers; Phoenix self-hosted is the "no third party touches PHI at all" answer.
- The **masking/redaction hook** — Langfuse's documented masking + data-retention + data-deletion controls are the observability-side complement to the week-8 Safe-Harbor scrub, and the memo should say which one it relies on.
- The **residency line** that connects to the payer-audit posture in weeks 9–10: separated regions, no cross-region workspaces, and who can be contracted with.

### Finance — *"Payments feel flaky and finance complains about 'noise' at month-end. Give me visibility so I'm not the last to know."*

Week 7 asks for structured tracing on the payment span, a daily ledger-vs-settlement reconciliation job with a break report, and one alert. **This day answers "who owns the tooling this control runs on, and can we still produce this evidence in three years?"** The reconciliation is not a dashboard — the packet calls the gap **SOX-material**, and Sam is in the room. A SOX-relevant control's tooling carries obligations a hobby-tier trace viewer does not: retention long enough to cover an audit period, an immutable-enough record, access control over who can see payment payloads, and vendor continuity.

Concretely, this day's landscape supplies:
- **Retention as a decision axis, not a feature bullet.** Arize AX Free retains 15 days and Pro 30 days; Langfuse Hobby is 30 days, Core 90 days, and **Pro is 3 years**. An audit-relevant control whose evidence evaporates in 15 days is not a control. This is the finance memo's deciding constraint.
- **Vendor continuity as an auditable risk.** Helicone's maintenance-mode notice is exactly the kind of fact a SOX control owner has to disclose — and exactly the kind of fact a stale model will not surface. It is the cleanest teaching example of why the memo requires verified sources with dates.
- **Audit logs and fine-grained RBAC**, which sit behind Langfuse's Enterprise/Teams tiers and LangSmith Enterprise — so "who could view raw payment payloads, and can we prove it?" has a price attached.
- **Payment payloads leaving the boundary** (PANs, account identifiers, PII in trace inputs/outputs) ties straight back to the week-5/6 PCI work: the residency and masking questions are the same questions, asked of a different system.

## Concept IDs

Scoped to this day (vendor landscape + the decision axes). Trace/span anatomy (w07d1), golden signals + SLOs (w07d4), and output guardrails (w07d5) are excluded.

- **`observability-deployment-topologies`** — SaaS / regional SaaS / hybrid (SaaS control plane + self-hosted data plane) / self-hosted / air-gapped; why "where does the trace payload live" is a data-classification decision, and what self-hosting actually costs (Langfuse = web + worker + Postgres + ClickHouse + Redis + S3, all UTC).
- **`otel-native-vs-proprietary-tracing`** — every vendor ingests OTLP, but each maps into its own model (Langfuse mapping layer, HTTP-only no gRPC; LangSmith's published `gen_ai.*` → run-tree table; Phoenix built on OpenInference; Helicone as gateway/proxy). The lock-in decision is the instrumentation SDK, not the backend; Collector fanout is the escape hatch.
- **`source-available-vs-osi-open-source`** — MIT (Langfuse, except `ee/`) vs Apache 2.0 (Helicone, OpenInference, OpenLLMetry) vs Elastic License 2.0 (Phoenix — source-available, not OSI, plus a patent notice) vs proprietary/open-core; which distinction the client's counsel actually cares about.
- **`observability-pricing-meters`** — units vs requests vs spans+GB+retention vs normalized LCU/LSU; why prices are incomparable without a stated monthly volume and trace→span fan-out ratio, and why retention window is a first-class cost axis for audit-relevant controls.
- **`trace-data-residency-and-baa`** — separated cloud regions, dedicated HIPAA regions, signed BAAs as a precondition to processing PHI, EU contracting entities, and masking/retention/deletion as the customer-side controls that reduce what ever reaches the vendor.
- **`vendor-continuity-risk`** — acquisition, maintenance mode, and repricing as first-class inputs to a signed recommendation; how to check (release cadence, changelog dates, license file, vendor blog) rather than recall.
