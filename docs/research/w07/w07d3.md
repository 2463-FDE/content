## Reviewed claims

- Inventories organize managed nodes into groups and variables; dynamic inventory plugins can retrieve inventory from external sources. This lesson uses static synthetic inventory only. — [Inventory introduction](https://docs.ansible.com/ansible/latest/inventory_guide/intro_inventory.html), [Dynamic inventory](https://docs.ansible.com/ansible/latest/inventory_guide/intro_dynamic_inventory.html)
- Playbooks are YAML automation blueprints containing ordered plays and tasks. Modules aim for desired state where supported; shell commands are not automatically idempotent. — [Playbooks](https://docs.ansible.com/ansible/latest/playbook_guide/playbooks_intro.html), [Intro to modules](https://docs.ansible.com/ansible/latest/module_plugin_guide/modules_intro.html)
- Roles package tasks, handlers, defaults, variables, files, templates and metadata into a known structure. Collections distribute roles, modules and plugins and must be pinned and reviewed like other dependencies. — [Roles](https://docs.ansible.com/ansible/latest/playbook_guide/playbooks_reuse_roles.html), [Collections](https://docs.ansible.com/ansible/latest/collections_guide/index.html)
- Handlers run when notified by a changed task, usually once after the relevant play section; they are appropriate for change-triggered operations such as service restarts. — [Handlers](https://docs.ansible.com/ansible/latest/playbook_guide/playbooks_handlers.html)
- Check mode predicts changes only where modules support it; diff mode can expose sensitive file content. Neither is proof of production safety. — [Check and diff mode](https://docs.ansible.com/ansible/latest/playbook_guide/playbooks_checkmode.html)

## Boundary

Terraform owns declared infrastructure objects; Ansible owns reviewed host/application configuration. The pattern is a responsibility split, not a guarantee that either tool makes arbitrary commands idempotent.
