# w07d1 — Terraform foundations and plan discipline

**Verified:** 2026-10-14  
**Authority:** provisionally authoritative LTM derivative, Week 7 MON; current product behavior checked against first-party documentation listed below. No cloud account or command execution was used.

## Source-assigned scope

IaC judgement; declarative versus imperative work; idempotence; Terraform write → plan → apply workflow; HCL providers, resources, data sources, variables and outputs; local versus remote state; lifecycle and teardown; AWS and Google provider/state comparisons. The lesson uses inert configuration and a saved illustrative plan only. It never runs `terraform apply`, creates credentials, or provisions resources.

## Reviewed claims

- Terraform configuration declares resources and data sources through provider plugins; providers expose resource types and data sources. Provider requirements and versions belong in the configuration and lock file. — [Providers](https://developer.hashicorp.com/terraform/language/providers), [Resources](https://developer.hashicorp.com/terraform/language/resources), [Data sources](https://developer.hashicorp.com/terraform/language/data-sources)
- Terraform state binds configuration addresses to remote objects. State may contain sensitive values, so access control and storage design matter even when configuration omits secrets. — [State purpose](https://developer.hashicorp.com/terraform/language/state/purpose), [Sensitive data in state](https://developer.hashicorp.com/terraform/language/state/sensitive-data)
- `terraform plan` previews proposed actions; a saved plan can be reviewed before a separately authorized apply. A plan is evidence to inspect, not permission to change infrastructure. — [Plan command](https://developer.hashicorp.com/terraform/cli/commands/plan)
- Backends determine where state is stored and may support state locking. The S3 and GCS backend pages define provider-specific configuration; the curriculum compares them without claiming equivalence. — [S3 backend](https://developer.hashicorp.com/terraform/language/backend/s3), [GCS backend](https://developer.hashicorp.com/terraform/language/backend/gcs)
- Terraform language is declarative, while provisioners are a last resort because Terraform cannot model their behavior predictably. Configuration management remains a separate responsibility. — [Provisioners](https://developer.hashicorp.com/terraform/language/resources/provisioners/syntax)

## Teaching boundary

Judge from ownership, state, lifecycle, evidence, and rollback. Do not teach command recall. Any provider authentication detail is a reviewed design row only; PR25 owns cloud-path and certification surfaces.
