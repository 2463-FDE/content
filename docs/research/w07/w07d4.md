## Source-assigned scope

CI/CD for AI systems; automated eval and regression gates; staged rollout; Terraform plan/apply pipeline as architecture; AI-assisted review/eval authoring; real GitHub MCP in the source program; infrastructure tests. This repository teaches the control shape without credentials, GitHub writes, MCP calls, provider calls, apply, or deployment.

## Reviewed claims

- GitHub Actions permissions can be restricted with the `permissions` key; untrusted pull-request code and secrets require explicit threat review. Environments can require reviewers before a job accesses environment secrets. — [Workflow permissions](https://docs.github.com/en/actions/writing-workflows/workflow-syntax-for-github-actions#permissions), [Deployment environments](https://docs.github.com/en/actions/managing-workflow-runs-and-deployments/managing-deployments/managing-environments-for-deployment)
- Terraform plan files may contain sensitive data and should be treated as sensitive artifacts. A reviewed saved plan can be applied only by a separately authorized step; the lesson never performs that step. — [Plan command](https://developer.hashicorp.com/terraform/cli/commands/plan)
- Ansible check mode is a prediction with module-specific support, not an execution guarantee. — [Check mode](https://docs.ansible.com/ansible/latest/playbook_guide/playbooks_checkmode.html)
- Claude Code's GitHub Actions integration supports repository automation, but its security guidance requires secrets management, constrained permissions, and human review. Generated findings and patches do not own merge or deployment authority. — [Claude Code GitHub Actions](https://code.claude.com/docs/en/github-actions), [Claude Code security](https://code.claude.com/docs/en/security)
- Evaluation gates should pin fixtures, thresholds and expected failure behavior. Model-assisted grading is not a substitute for deterministic syntax, schema, policy and security checks where those exist.

## Gate order

Format/validate → deterministic tests → policy/security scan → static Terraform plan → plan review → AI-system eval threshold → human approval → separately authorized change. Rollback and evidence are designed before approval, not after failure.
