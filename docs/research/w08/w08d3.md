# w08d3 — Correlate model, agent, tool, and Kafka work

**Verified:** 2026-10-14  
**Authority:** provisionally authoritative LTM derivative, Week 8 WED; reviewed W6 messaging and prior observability research.

## Source-assigned scope

Trace IDs; span attribution; cross-agent correlation; HTTP and Kafka context propagation; dashboards and alert design; structured logging; situation session tracing a bad answer to root cause.

## Reviewed claims

- A trace is a graph of spans for one operation; parent/child relationships and links express causal structure. Logs can carry trace and span identifiers for correlation, while metrics aggregate behavior. — [OpenTelemetry traces](https://opentelemetry.io/docs/concepts/signals/traces/), [Logs data model](https://opentelemetry.io/docs/specs/otel/logs/data-model/)
- Messaging propagation crosses an asynchronous boundary. OpenTelemetry messaging conventions model producer and consumer operations; context travels in message metadata, not in a partition offset. — [Messaging spans](https://opentelemetry.io/docs/specs/semconv/messaging/messaging-spans/)
- GenAI agent conventions distinguish agent invocation, model inference and tool execution. Correlation must preserve the user operation, model attempt, tool call, retry and guardrail/evaluation result without claiming they are one synchronous stack. — [GenAI agent spans](https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/gen-ai-agent-spans.md)
- Structured logs require stable fields, levels, timestamps and identifiers. Payload capture is minimized; trace IDs and safe business correlation IDs are enough for many incident paths.
- A dashboard is not observability by itself. A useful panel maps signal → threshold or query → client consequence → owner → runbook.
