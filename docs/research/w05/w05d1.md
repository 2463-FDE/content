## Source-authoritative scope

The LTIM curriculum assigns Monday eight topics: property-graph primitives; graph/relational/vector comparison; `MATCH`, `CREATE`, and `MERGE`; filtering and aggregation; Docker and Neo4j Browser; entities; relationships; and decision/action surfaces. The milestone is a Neo4j domain model of the client system.

## Verified claims

1. Neo4j's property-graph model represents **nodes**, typed/directed **relationships**, **labels**, and key-value **properties**. Both nodes and relationships may hold properties.
2. `MATCH` describes graph patterns to read. `CREATE` creates patterns. `MERGE` matches an entire pattern or creates it when absent; it is not a blanket uniqueness guarantee. Concurrent uniqueness requires a matching constraint.
3. Graph, relational, and vector systems answer different access patterns. A graph is valuable when the path and relationship semantics are part of the question. A vector index retrieves by embedding similarity; it does not by itself assert that a business relationship is true.
4. Neo4j documents local Docker operation and Browser as supported development paths. The lesson may show commands as inert examples, but this task must not provision infrastructure or touch an external account.
5. A useful domain model starts from client questions and decision/action surfaces, then chooses the smallest entities and relationships needed to answer those questions. This is modeling guidance, not a Neo4j guarantee.
