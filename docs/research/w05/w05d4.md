## Source-authoritative scope

Thursday covers the graph as institutional memory; Chroma plus Neo4j retrieval; a LangGraph node querying Neo4j; grounding evaluation; agent context assembly; query cost/performance; Neo4j through an MCP workflow; and the source-assigned AWS/GCP graph-topology comparison.

## Verified claims

1. Chroma supports embedding-based collections and similarity retrieval. Neo4j represents explicit entities and relationships. A hybrid design can use vector retrieval for semantic candidates and graph traversal for connected evidence; neither store should be called universally superior.
2. A LangGraph node can call application code that queries Neo4j, but the graph database remains an external dependency with its own timeout, authorization, and failure behavior. The node should return a bounded evidence object rather than an unbounded database dump.
3. Neo4j's Python performance guidance emphasizes parameterized queries, transaction choices, and database selection. Cypher plans can be inspected with `EXPLAIN` and measured with `PROFILE`; `PROFILE` executes the query and should not be used casually on write queries.
4. A context pack should carry source/provenance, graph paths, freshness, limits, and unresolved conflicts. Grounding evaluation should separately inspect retrieval relevance, path/provenance support, answer support, and refusal/abstention behavior.
5. Neo4j documents MCP tooling, but an MCP server is a protocol/tool surface—not an authorization boundary. Use allowlisted read operations and application-enforced policy. This lesson performs no external connection.
6. Source curriculum requires a topology comparison: self-managed graph hosts on EC2/GCE versus Aura marketplace availability, private networking choices, and data gravity. Marketplace listings establish availability, not suitability, price parity, or private-connectivity equivalence. Exact eligibility, regions, networking, and prices must be verified for the client's dated configuration.
