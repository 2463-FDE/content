# w03d3 — Agent framework landscape (alt-research)

LangChain/LangGraph v1 vs CrewAI vs OpenAI Agents SDK vs Microsoft Agent Framework (ex-AutoGen). Research brief for authoring; every claim is source-backed and URL-verified 2026-07.

version-stamps:
  - LangChain 1.0 + LangGraph 1.0: both GA on 2025-10-22 (verified 2026-07) — `create_agent` + middleware + standard content blocks; LangChain agents run on the LangGraph durable runtime
  - OpenAI Agents SDK: Python SDK (`openai-agents`), production-ready successor to the experimental Swarm project; primitives = agents / handoffs / guardrails / sessions / tracing (verified 2026-07)
  - CrewAI: 1.15.1, released 2026-06-27, requires Python >=3.10,<3.14 (verified 2026-07 via PyPI) — dual model of Crews (role-based, autonomous) + Flows (event-driven, deterministic); standalone, independent of LangChain
  - Microsoft Agent Framework: 1.0 GA on 2026-04-03 (`agent-framework` pip package), the direct successor that MERGES AutoGen + Semantic Kernel; AutoGen is now legacy/migration-only (verified 2026-07)

STALE-ADVICE WARNING for authoring: models trained before 2026 will describe "AutoGen" and "Semantic Kernel" as two separate live Microsoft frameworks, and LangChain as a pre-1.0 chains library. Both are wrong now. AutoGen + Semantic Kernel have been unified into Microsoft Agent Framework (GA 2026-04-03), and LangChain/LangGraph shipped stable 1.0 on 2025-10-22 re-centered on the agent loop. Do not seed the day from pre-2026 memory.

## Claims (each MUST carry a source)

- LangChain and LangGraph reached their first stable major versions (1.0) simultaneously on 2025-10-22; LangGraph 1.0 is billed as the first stable major release in the "durable agent framework" space after a year-plus of production adoption. — [LangChain and LangGraph reach v1.0 — LangChain Blog](https://www.langchain.com/blog/langchain-langgraph-1dot0)
- LangChain 1.0 re-centers the library on the core agent loop: the new `create_agent` abstraction is "the fastest way to build an agent with any model provider" and runs a simple loop (send request to model, handle tool calls or return final answer, repeat). — [LangChain and LangGraph reach v1.0 — LangChain Blog](https://www.langchain.com/blog/langchain-langgraph-1dot0)
- LangChain 1.0 introduces middleware — customizable hooks throughout agent execution (e.g. human-in-the-loop approval/edit/reject of tool calls, context-summarization) — plus standard content blocks that give consistent content types (reasoning traces, citations, tool calls) across providers so you can swap models without rewriting parsing. — [LangChain and LangGraph reach v1.0 — LangChain Blog](https://www.langchain.com/blog/langchain-langgraph-1dot0)
- LangChain agents are built on LangGraph, so the two are layered rather than competing: start with LangChain's high-level API and drop down to the LangGraph durable runtime (built-in persistence, resumable state, human-in-the-loop) when you need explicit graph control. — [LangChain and LangGraph reach v1.0 — LangChain Blog](https://www.langchain.com/blog/langchain-langgraph-1dot0)
- The OpenAI Agents SDK is a lightweight, production-ready framework explicitly described as "a production-ready upgrade of our previous experimentation for agents, Swarm." — [OpenAI Agents SDK — official docs](https://openai.github.io/openai-agents-python/)
- The OpenAI Agents SDK is built on a small set of primitives: Agents (LLMs with instructions + tools), Handoffs (delegate to another agent), Guardrails (validate inputs/outputs), and Sessions (persistent conversation memory), plus built-in tracing for visualization and debugging. — [OpenAI Agents SDK — official docs](https://openai.github.io/openai-agents-python/)
- In the OpenAI Agents SDK, handoffs are implemented as tools exposed to the LLM: a handoff to an agent named "Refund Agent" surfaces as a tool named `transfer_to_refund_agent`, so routing/delegation is just the model choosing a tool. — [Handoffs — OpenAI Agents SDK](https://openai.github.io/openai-agents-python/handoffs/)
- Although the OpenAI Agents SDK defaults to the OpenAI Responses API, it is not OpenAI-only: it ships extension points for other providers via LiteLLM and Any-LLM adapters, so it can drive non-OpenAI models. — [OpenAI Agents SDK — official docs](https://openai.github.io/openai-agents-python/)
- CrewAI exposes two complementary orchestration models: Crews (autonomous, role-based agent collaboration with flexible decision-making) and Flows (event-driven, deterministic control with precise state management and conditional branching); the README states "the true power of CrewAI emerges when combining Crews and Flows." — [crewAI README — GitHub](https://github.com/crewAIInc/crewAI/blob/main/README.md)
- CrewAI Flows are event-driven workflows built from `@start()` entry-point methods and `@listen()` methods triggered by prior method outputs, with multi-listener `or_`/`and_` operators, router-based conditional branching, and either unstructured (dict) or structured (Pydantic) per-execution state. — [Flows — CrewAI Docs](https://docs.crewai.com/en/concepts/flows)
- CrewAI is a standalone framework, independent of LangChain: the current PyPI release (1.15.1, 2026-06-27) describes it as "built entirely from scratch — completely independent of LangChain or other agent frameworks" and requires Python >=3.10,<3.14. — [crewai — PyPI](https://pypi.org/project/crewai/)
- Microsoft Agent Framework is the direct successor to BOTH AutoGen and Semantic Kernel, created by the same teams; it combines AutoGen's simple single-/multi-agent abstractions with Semantic Kernel's enterprise features (session state, type safety, filters, telemetry) and adds graph-based Workflows for explicit multi-agent orchestration. — [Microsoft Agent Framework Overview — Microsoft Learn](https://learn.microsoft.com/en-us/agent-framework/overview/)
- Microsoft Agent Framework splits capabilities into Agents (LLM + tools + MCP, open-ended/conversational tasks) and Workflows (graph-based, type-safe routing with checkpointing and human-in-the-loop for well-defined multi-step processes); guidance is "if you can write a function to handle the task, do that instead of using an AI agent." — [Microsoft Agent Framework Overview — Microsoft Learn](https://learn.microsoft.com/en-us/agent-framework/overview/)
- Microsoft ships an official AutoGen-to-Agent-Framework migration guide (page dated 2026-04-01), confirming AutoGen is now a legacy/migration source rather than the recommended target for new work. — [AutoGen to Microsoft Agent Framework Migration Guide — Microsoft Learn](https://learn.microsoft.com/en-us/agent-framework/migration-guide/from-autogen/)

## Concept IDs (interview question-bank seeds)

Each id carries a one-line definition so the question-bank author seeds from a fixed meaning, not from prose.

- agent-orchestration-framework — a library that provides the runtime and abstractions for building LLM agents (the agent loop, tool calling, state/memory, and multi-agent coordination) instead of hand-rolling that plumbing; the 2026 landscape is LangChain/LangGraph, OpenAI Agents SDK, CrewAI, and Microsoft Agent Framework.
- langchain-langgraph-v1 — LangChain 1.0 and LangGraph 1.0 (both GA 2025-10-22): LangChain gives a high-level `create_agent` loop plus middleware and provider-agnostic content blocks, layered on the LangGraph durable runtime (persistent, resumable, human-in-the-loop graph execution) you drop into for explicit control.
- openai-agents-sdk-handoffs — the OpenAI Agents SDK's model of multi-agent delegation, where an agent hands control to another agent via a tool call (e.g. `transfer_to_refund_agent`); the SDK's minimal primitive set is agents, handoffs, guardrails, sessions, and tracing, and it is the production successor to Swarm.
- crewai-crews-vs-flows — CrewAI's two orchestration styles: Crews are autonomous role/goal/backstory-based agent teams optimized for collaborative decision-making, while Flows are event-driven, deterministic pipelines (`@start`/`@listen`, routers, Pydantic state) that embed Crews as steps; CrewAI is a standalone framework independent of LangChain.
- microsoft-agent-framework — Microsoft's 1.0 (GA 2026-04-03) unification of AutoGen and Semantic Kernel into one SDK, pairing AutoGen's agent abstractions with Semantic Kernel's enterprise features and adding graph-based Workflows; AutoGen and Semantic Kernel are now legacy/migration sources, not the recommended target for new projects.
- agent-framework-selection-tradeoffs — the decision axes for picking among these frameworks: control model (autonomous agent loop vs explicit graph/workflow), provider lock-in (OpenAI-first vs provider-agnostic), enterprise/state features, ecosystem maturity, and whether the task even needs an agent versus a plain function.
