## Claims

### The agent core
- **An agent is "a model calling tools in a loop until a given task is complete."** `create_agent` is LangChain 1.0's high-level factory for this loop, built on the LangGraph runtime. [Agents — Docs by LangChain](https://docs.langchain.com/oss/python/langchain/agents)
- **`create_agent` verified signature** (key params): `model: str | BaseChatModel`, `tools`, `system_prompt: str | SystemMessage | None`, `middleware: Sequence[AgentMiddleware] = ()`, `response_format`, `checkpointer`, `store`. `model` accepts a provider-qualified string or an initialized model instance. The current curriculum example uses the verified Claude API alias `"anthropic:claude-sonnet-5"`; the older `claude-sonnet-4-5-20250929` reference example is a legacy snapshot. [create_agent — LangChain Reference](https://reference.langchain.com/python/langchain/agents/factory/create_agent)
- **Minimal usage:** `from langchain.agents import create_agent` then `agent = create_agent(model="...", tools=[...], system_prompt="...")`; run with `agent.invoke({...})` / `await agent.ainvoke({...})`. [Agents — Docs by LangChain](https://docs.langchain.com/oss/python/langchain/agents)

### Structured output
- **`response_format` folds structured output into the main model↔tools loop.** It accepts a `ToolStrategy`, `ProviderStrategy`, or a Pydantic model class; raw schemas are auto-wrapped based on model support. Integrating it into the core loop reduces latency and cost by "eliminating extra LLM calls." [create_agent — LangChain Reference](https://reference.langchain.com/python/langchain/agents/factory/create_agent) · [LangChain & LangGraph 1.0 — LangChain Blog](https://www.langchain.com/blog/langchain-langgraph-1dot0)

### Middleware (the production customization primitive)
- **Middleware is the customization primitive**: "each piece handles one concern, hooks into the agent loop at the right moment, and composes freely." Categories span execution environment, context management, fault tolerance, guardrails, and human steering. [Agents — Docs by LangChain](https://docs.langchain.com/oss/python/langchain/agents)
- **Verified hook names** on `AgentMiddleware`: `before_agent`, `before_model`, `wrap_model_call`, `after_model`, `wrap_tool_call`, `after_agent`. [Middleware — LangChain Reference](https://reference.langchain.com/python/langchain/middleware/)
- **Verified built-in middleware classes** include: `SummarizationMiddleware`, `HumanInTheLoopMiddleware`, `ModelCallLimitMiddleware`, `ToolCallLimitMiddleware`, `ModelFallbackMiddleware`, `PIIMiddleware`, `TodoListMiddleware`, `LLMToolSelectorMiddleware`, `ToolRetryMiddleware`, `LLMToolEmulator`, `ContextEditingMiddleware`, `ShellToolMiddleware`, `FilesystemFileSearchMiddleware`. [Middleware — LangChain Reference](https://reference.langchain.com/python/langchain/middleware/)
- **Production framing:** `HumanInTheLoopMiddleware` pauses the agent before high-stakes tool calls for approve/edit/reject; `SummarizationMiddleware` (via `before_model`) summarizes history before context overflow; `PIIMiddleware` masks/redacts/hashes PII on inputs, outputs, and tool outputs. [Middleware Overview — Docs by LangChain](https://docs.langchain.com/oss/python/langchain/middleware/overview)

### MCP integration
- **`MultiServerMCPClient` bridges MCP servers into LangChain tools.** `tools = await client.get_tools()` returns LangChain `BaseTool`s, passed straight to `create_agent(model, tools)`. Client is **stateless by default** — each tool invocation opens a fresh `ClientSession`, executes, and cleans up; use `client.session()` for persistent stateful connections. [MCP — Docs by LangChain](https://docs.langchain.com/oss/python/langchain/mcp) · [langchain-mcp-adapters (GitHub)](https://github.com/langchain-ai/langchain-mcp-adapters)
- **Transport config** — stdio spawns a local subprocess (`{"transport": "stdio", "command": "python", "args": [...]}`); Streamable HTTP targets a remote endpoint (`{"transport": "http", "url": "http://localhost:8000/mcp"}`). [MCP — Docs by LangChain](https://docs.langchain.com/oss/python/langchain/mcp)
- **MCP tool-error handling:** by default a failed MCP tool returns to the model as a `ToolMessage` with `status="error"` (agent can read and retry); set `handle_tool_errors=False` to raise instead. [langchain-mcp-adapters (GitHub)](https://github.com/langchain-ai/langchain-mcp-adapters)

### MCP protocol facts (for grounding the transport choice)
- **stdio** remains a standard transport in the latest revision: newline-delimited messages over the standard streams of a client-launched subprocess. [MCP Transports — Spec 2026-07-28](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports)
- **Streamable HTTP** remains the network transport: each message is an HTTP POST to one MCP endpoint, with a JSON response or request-scoped SSE stream. Servers **MUST** validate the `Origin` header and **SHOULD** bind to localhost when local. [MCP Streamable HTTP — Spec 2026-07-28](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http)

## Concept IDs

Scoped tightly to this day (production single agent = `create_agent` + middleware + structured output + MCP integration). Later-day topics (multi-agent orchestration, evals, deployment) deliberately excluded.

- **`create-agent-loop`** — LangChain 1.0's `create_agent` factory and the "model calls tools in a loop until the task is complete" runtime it builds on LangGraph; the entry point for a single production agent.
- **`agent-middleware-hooks`** — The `AgentMiddleware` extension model and its lifecycle hooks (`before_agent`, `before_model`, `wrap_model_call`, `after_model`, `wrap_tool_call`, `after_agent`) as the composable primitive for customizing the agent loop.
- **`response-format-structured-output`** — Folding structured output into the agent loop via `response_format` (`ToolStrategy` / `ProviderStrategy` / Pydantic model), eliminating a separate LLM call.
- **`builtin-production-middleware`** — Ship-ready middleware for production concerns: `HumanInTheLoopMiddleware` (approve/edit/reject high-stakes tool calls), `SummarizationMiddleware` (context-overflow control), `PIIMiddleware` (mask/redact/hash), and call-limit / fallback / retry classes.
- **`mcp-multiserver-client`** — `MultiServerMCPClient` from `langchain-mcp-adapters`: bridging MCP servers into LangChain `BaseTool`s via `get_tools()`, the stateless-by-default session model, and MCP tool-error handling.
- **`mcp-transports-stdio-vs-http`** — Choosing between the two transports retained by the latest 2026-07-28 revision: stdio (local subprocess, JSON-RPC over stdin/stdout) vs Streamable HTTP (single endpoint, request-scoped optional SSE, Origin-validation security), and how each is configured in the client.
