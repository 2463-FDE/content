## Claims (each MUST carry a source)

- Prompt work should start from defined success criteria and empirical evaluation rather than wording changes without a measurable target. — [Anthropic — Prompt engineering overview](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/overview)
- Clear instructions, examples, roles, and XML tags are documented techniques for making Claude prompts easier to follow and evaluate. — [Anthropic — Prompting best practices](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices)
- OpenAI similarly recommends structuring prompts around instructions, context, examples, and task-specific evaluation. — [OpenAI — Prompt engineering](https://developers.openai.com/api/docs/guides/prompt-engineering)
- Structured Outputs constrain responses to a supplied JSON schema; downstream code should still handle refusals and incomplete responses explicitly. — [OpenAI — Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)
- For `bedrock-runtime` in `us-east-1`, AWS lists `us.anthropic.claude-haiku-4-5-20251001-v1:0` as a US geo inference-profile ID. — [AWS — Claude Haiku 4.5 model card](https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-anthropic-claude-haiku-4-5.html)
