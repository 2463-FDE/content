## Claims (each MUST carry a source)

- Application configuration, including provider keys and model IDs, belongs in environment-backed configuration rather than source code. — [The Twelve-Factor App — Config](https://12factor.net/config)
- Anthropic documents API status codes, request IDs, and error shapes that a transport layer can use for bounded retry and correlation. — [Anthropic — API errors](https://platform.claude.com/docs/en/api/errors)
- Official SDKs expose streaming and typed errors; streaming uses server-sent events and can fail after the response begins. — [Anthropic — SDKs](https://platform.claude.com/docs/en/cli-sdks-libraries/overview) and [Anthropic — Streaming](https://platform.claude.com/docs/en/build-with-claude/streaming)
- Claude API model IDs from generation 4.6 onward are dateless canonical, pinned IDs such as `claude-sonnet-5`; they are not evergreen aliases. Earlier models such as Haiku 4.5 use dated snapshots, with short convenience aliases only on the Claude API. — [Anthropic — Model IDs and versioning](https://platform.claude.com/docs/en/about-claude/models/model-ids-and-versions)
- Claude Haiku 4.5's Claude API snapshot is `claude-haiku-4-5-20251001`, and its status was active with a tentative retirement date not sooner than 2026-10-15 when verified. Partner platforms such as Amazon Bedrock set separate lifecycle schedules. — [Anthropic — Models overview](https://platform.claude.com/docs/en/models/overview) and [Anthropic — Model deprecations](https://platform.claude.com/docs/en/about-claude/model-deprecations)
- AWS's Bedrock sample exports the API key as `AWS_BEARER_TOKEN_BEDROCK`; teaching config should read that value from the environment rather than embed it. — [AWS — Claude Haiku 4.5 model card](https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-anthropic-claude-haiku-4-5.html)
- For boto3 `bedrock-runtime` in `us-east-1`, AWS lists `us.anthropic.claude-haiku-4-5-20251001-v1:0` and `us.anthropic.claude-sonnet-5` as US geo inference-profile IDs. It also lists global-profile alternatives. — [AWS — Claude Haiku 4.5 model card](https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-anthropic-claude-haiku-4-5.html) and [AWS — Claude Sonnet 5 model card](https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-anthropic-claude-sonnet-5.html)
- AWS warns that `bedrock-runtime` requires a geo or global inference-profile ID for these models; a bare ID is not supported there for on-demand throughput. Geo/global profiles can route outside the source Region and do not guarantee single-Region residency. AWS documents the bare IDs for its separate `bedrock-mantle` endpoint. — [AWS — Claude Haiku 4.5 model card](https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-anthropic-claude-haiku-4-5.html) and [AWS — Claude Sonnet 5 model card](https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-anthropic-claude-sonnet-5.html)

## Trainer troubleshooting note

The snippets use boto3 `bedrock-runtime`, so keep the statically verified inference-profile IDs rather than substituting a Claude API alias. If an organization blocks `us.` routing or requires strict single-Region processing, do not guess a prefix: check the AWS model card and the organization's enabled/approved profile in the target Region. This static review did not inspect an account or make a Bedrock call; organization-specific enablement remains a bounded specialist verification.
