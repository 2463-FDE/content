# w06d1 Research Brief — Coding-Agents Landscape, Claude Code Focus

**Researched:** 2026-07-01
**Scope:** The agentic coding CLI landscape and Claude Code as the primary FDE tool: install/surfaces, the permission system, CLAUDE.md memory, skills, and hooks.

## Version stamps (as of 2026-07-01)

- **Claude Code** — native installer auto-updates; docs live at code.claude.com. Doc-referenced feature floors: auto memory requires v2.1.59+, `/cd` requires v2.1.169+, `/run`//`/verify` bundled skills require v2.1.145+.
- **OpenAI Codex CLI** — open source, written in Rust; install via `curl -fsSL https://chatgpt.com/codex/install.sh | sh`; included in ChatGPT Plus/Pro/Business/Edu/Enterprise plans.
- **Gemini CLI** — v0.49.0 (released 2026-06-25), Apache-2.0, `npm install -g @google/gemini-cli`; free OAuth tier 60 req/min and 1,000 req/day; 1M-token context with Gemini 3 models.
- **Terminal-Bench** — versions 2.0 and 2.1 live; 3.0 "coming soon."
- **Agent Skills** — open standard at agentskills.io, originated by Anthropic; adopted by Claude Code, Codex, Gemini CLI, Cursor, GitHub Copilot, Goose, OpenCode, and dozens more.

## Claims

### The landscape: terminal-native coding agents have converged on a common shape

1. **The big three vendor CLIs are Claude Code (Anthropic), Codex CLI (OpenAI), and Gemini CLI (Google), and all three are terminal-first agents that read code, edit files, and run commands.** Claude Code: "an agentic coding tool that reads your codebase, edits files, runs commands, and integrates with your development tools." [Claude Code Overview](https://code.claude.com/docs/en/overview) · [Codex CLI](https://developers.openai.com/codex/cli/) · [Gemini CLI (GitHub)](https://github.com/google-gemini/gemini-cli)

2. **The three tools mirror each other's core mechanics: an instruction memory file (CLAUDE.md / AGENTS.md / GEMINI.md), approval or sandbox modes before running commands, and MCP support for external tools.** Codex CLI: "choose the approval mode that matches your comfort level before Codex edits or runs commands," configured via AGENTS.md and config.toml. Gemini CLI has GEMINI.md context files and MCP servers in `~/.gemini/settings.json`. [Codex CLI](https://developers.openai.com/codex/cli/) · [Gemini CLI (GitHub)](https://github.com/google-gemini/gemini-cli)

3. **Claude Code interoperates with AGENTS.md rather than reading it natively: the docs recommend a CLAUDE.md containing `@AGENTS.md` (an import) or a symlink, so one instruction file serves multiple agents.** "Claude Code reads `CLAUDE.md`, not `AGENTS.md`... create a `CLAUDE.md` that imports it so both tools read the same instructions." [Memory — AGENTS.md](https://code.claude.com/docs/en/memory)

4. **The Agent Skills format is now a cross-vendor open standard: a skill is a folder with a `SKILL.md` (frontmatter `name` + `description` at minimum, plus instructions), loaded via three-stage progressive disclosure (discovery → activation → execution).** "At startup, agents load only the name and description of each available skill"; full instructions load only when a task matches. Originated by Anthropic; the client showcase includes Codex, Gemini CLI, Cursor, Copilot, VS Code, Goose, and others. [Agent Skills standard](https://agentskills.io)

5. **Terminal-Bench is the reference benchmark for terminal-based agents; versions 2.0 and 2.1 are live and 3.0 is announced.** Use it for "compare agent performance across Terminal-Bench versions and challenges" framing — specific scores churn too fast to hard-code in curriculum. [Terminal-Bench leaderboard](https://www.tbench.ai/leaderboard)

### Claude Code: CLI and surfaces

6. **Claude Code runs across terminal, VS Code/Cursor extension, JetBrains plugin, desktop app, and web (claude.ai/code); all surfaces share the same engine, so CLAUDE.md files, settings, and MCP servers work everywhere.** Native install: `curl -fsSL https://claude.ai/install.sh | bash`, then `claude` in any project. [Claude Code Overview](https://code.claude.com/docs/en/overview)

7. **The CLI is Unix-composable: `claude -p "<prompt>"` runs headless, accepts piped stdin (`tail -200 app.log | claude -p ...`), and chains in CI.** For CI auth without browser login, `claude setup-token` mints a one-year OAuth token used via `CLAUDE_CODE_OAUTH_TOKEN`. [Overview — pipe/script](https://code.claude.com/docs/en/overview) · [Authentication](https://code.claude.com/docs/en/authentication)

8. **Credential precedence is explicit: cloud-provider env flags (Bedrock/Vertex/Foundry) > `ANTHROPIC_AUTH_TOKEN` > `ANTHROPIC_API_KEY` > `apiKeyHelper` > `CLAUDE_CODE_OAUTH_TOKEN` > subscription OAuth from `/login`.** A stray `ANTHROPIC_API_KEY` overriding your subscription is a documented failure mode; check with `/status`. [Authentication](https://code.claude.com/docs/en/authentication)

### Claude Code: permissions

9. **Permission rules are evaluated deny → ask → allow, first match wins, and specificity does NOT change the order — a broad `Bash(aws *)` deny blocks a narrower `Bash(aws s3 ls)` allow, so deny rules can't carry allowlist exceptions.** "Rules are evaluated in order: deny, then ask, then allow. The first match in that order determines the outcome." [Configure permissions](https://code.claude.com/docs/en/permissions)

10. **Settings precedence: managed settings > CLI arguments > `.claude/settings.local.json` > `.claude/settings.json` (project, shareable) > `~/.claude/settings.json` (user). A deny at any level can't be re-allowed at another.** [Configure permissions — settings precedence](https://code.claude.com/docs/en/permissions)

11. **Permission modes (set via `defaultMode`): `default`, `acceptEdits`, `plan`, `auto` (research preview with background safety checks), `dontAsk`, and `bypassPermissions` — the last skips prompts except explicit `ask` rules and a circuit breaker on `rm -rf /` / `rm -rf ~`, and is documented as safe only in isolated containers/VMs.** [Configure permissions — permission modes](https://code.claude.com/docs/en/permissions)

12. **Rule syntax is `Tool` or `Tool(specifier)`: Bash rules use `*` globs with shell-operator awareness (compound commands must match each subcommand independently); Read/Edit rules use gitignore-style paths with `//` absolute, `~/` home, `/` project-root anchors; WebFetch uses `domain:` matching.** Bash argument-constraining patterns are documented as fragile (e.g., `curl` URL filters bypassable via flags/redirects/variables) — the docs recommend deny rules + WebFetch domain allows or PreToolUse hooks instead. [Configure permissions — rule syntax](https://code.claude.com/docs/en/permissions)

13. **Permissions are enforced by the harness, not the model: "Permission rules are enforced by Claude Code, not by the model. Instructions in your prompt or CLAUDE.md shape what Claude tries to do, but they don't change what Claude Code allows."** Sandboxing is a complementary OS-level layer for Bash and its child processes; permissions + sandbox = defense-in-depth. [Configure permissions](https://code.claude.com/docs/en/permissions)

### Claude Code: CLAUDE.md and memory

14. **CLAUDE.md scopes load in order broadest → most specific: managed policy (e.g., `/Library/Application Support/ClaudeCode/CLAUDE.md`), user (`~/.claude/CLAUDE.md`), project (`./CLAUDE.md` or `./.claude/CLAUDE.md`), local (`./CLAUDE.local.md`, gitignored). Discovery walks up the directory tree; subdirectory CLAUDE.md files load on demand when Claude reads files there.** [Memory](https://code.claude.com/docs/en/memory)

15. **CLAUDE.md supports `@path/to/file` imports (max depth 4 hops, load at launch, first external import prompts for approval), and the guidance is to keep each file under 200 lines — imported files still cost context.** Path-scoped `.claude/rules/*.md` files with `paths:` frontmatter load only when Claude touches matching files. [Memory — imports and rules](https://code.claude.com/docs/en/memory)

16. **Auto memory (v2.1.59+, on by default) is the second memory system: Claude writes its own notes to `~/.claude/projects/<project>/memory/` with a `MEMORY.md` index whose first 200 lines / 25KB load every session; topic files load on demand.** Audit/edit via `/memory` — everything is plain markdown. [Memory — auto memory](https://code.claude.com/docs/en/memory)

17. **CLAUDE.md is context, not enforcement: "Claude treats them as context, not enforced configuration. To block an action regardless of what Claude decides, use a PreToolUse hook instead."** [Memory](https://code.claude.com/docs/en/memory)

### Claude Code: skills and hooks

18. **A Claude Code skill is `SKILL.md` (YAML frontmatter + markdown body) in `~/.claude/skills/<name>/` (personal), `.claude/skills/<name>/` (project), plugin, or enterprise scope; the directory name becomes the `/name` command, and Claude also auto-invokes skills whose `description` matches the task. Custom commands (`.claude/commands/`) have been merged into skills.** Same-name precedence: enterprise > personal > project; nested monorepo skills get directory-qualified names like `apps/web:deploy`. [Skills](https://code.claude.com/docs/en/skills)

19. **Skills' key economics vs CLAUDE.md: "a skill's body loads only when it's used, so long reference material costs almost nothing until you need it." Claude Code extends the open standard with invocation control, subagent execution, and dynamic context injection (`` !`cmd` `` lines run before Claude reads the skill).** [Skills](https://code.claude.com/docs/en/skills) · [Agent Skills standard](https://agentskills.io)

20. **Hooks are user-defined shell commands, HTTP endpoints, or LLM prompts firing at lifecycle events — per session (`SessionStart`/`SessionEnd`), per turn (`UserPromptSubmit`, `Stop`), per tool call (`PreToolUse`, `PostToolUse`) — configured under `hooks` in settings files with tool-name matchers (exact, `|` lists, regex, `mcp__server__tool`).** [Hooks reference](https://code.claude.com/docs/en/hooks)

21. **Hook control channels: exit code 2 blocks the action and feeds stderr back to Claude (exit 1 is non-blocking); exit 0 with JSON gives fine-grained control (`permissionDecision: allow/deny/ask`, `continue: false`, `additionalContext`). A blocking PreToolUse hook takes precedence over allow rules, but hook "allow" decisions never bypass deny/ask permission rules.** [Hooks reference](https://code.claude.com/docs/en/hooks) · [Configure permissions — extend with hooks](https://code.claude.com/docs/en/permissions)

22. **Anthropic's official mental model for choosing a mechanism: facts you always need → CLAUDE.md; directory-conditional instructions → path-scoped rules; procedures/runbooks → skills; deterministic must-happen behavior → hooks; context-heavy side tasks → subagents.** "Procedures belong in skills. CLAUDE.md is for facts Claude should hold all the time." / "Use hooks for anything that should happen deterministically." [Steering Claude Code (Anthropic blog)](https://claude.com/blog/steering-claude-code-skills-hooks-rules-subagents-and-more)

## Teaching notes

- Lead with the harness-vs-model distinction (claims 13, 17): permissions and hooks are deterministic enforcement; CLAUDE.md and skills are steering. This is the single most load-bearing idea for FDEs deploying agents at clients.
- The landscape section should stress convergence (memory file + approval modes + MCP + skills standard) rather than horse-race benchmark numbers, which go stale in weeks.
- Avoid citing specific Terminal-Bench/SWE-bench scores from secondary blogs; they were not verifiable against primary sources at research time.
- Reports of Gemini CLI transitioning to "Antigravity CLI" appear in secondary sources only; the official repo shows active releases (v0.49.0, 2026-06-25) with no deprecation notice — do not teach the transition as fact.
