# w06d3 — Alt Research: Cursor, Aider & Copilot vs Claude Code

> Research brief for authoring. Verify-first; every claim is backed by an official/primary source fetched and confirmed 2026-07-01. Scope: the coding-agent alternatives landscape — what Cursor, Aider, and GitHub Copilot actually are today, how their designs differ from Claude Code (our pick), and how to read the landscape without vendor marketing. Deep Claude Code internals, evals methodology, and multi-agent orchestration are other days' topics.

## Claims

### The landscape is a form-factor spectrum, not a feature checklist
- The four tools occupy distinct form factors: **Cursor** is an AI-native IDE (VS Code fork) with an in-editor agent plus cloud agents; **Copilot** is a platform spanning IDE extension, terminal CLI, and a GitHub-hosted cloud agent; **Aider** is a pure terminal pair-programmer; **Claude Code** is terminal-native first, with the same engine exposed in IDE, desktop, web, and CI surfaces. [Cursor Changelog](https://cursor.com/changelog) · [GitHub Copilot cloud agent — GitHub Docs](https://docs.github.com/copilot/concepts/agents/coding-agent/about-coding-agent) · [Aider — AI pair programming in your terminal](https://aider.chat/) · [Claude Code overview — official docs](https://code.claude.com/docs/en/overview)
- Convergence is real: every vendor now ships (a) an interactive agent that edits files and runs commands, (b) an async/cloud agent that works on delegated tasks, and (c) MCP support. The differentiators are context strategy, review/permission model, model access, and where the agent lives. (Synthesis across the four sources above.)

### Cursor — IDE-native agent, aggressively expanding to cloud/mobile
- Cursor's Agent "can complete complex coding tasks independently, run terminal commands, and edit code," with tools for **semantic search over an indexed codebase**, file ops, web search, terminal, and browser control; it auto-creates **checkpoints** ("snapshots of your codebase during an Agent session") for safe rollback, and supports queueing follow-up messages mid-run. [Agent Overview — Cursor Docs](https://cursor.com/docs/agent/overview)
- 2026 release cadence shows the direction of travel: 3.7 added **cloud subagents** (`/in-cloud` spins up subagents in isolated VMs, with local↔cloud session handoff); 3.8 expanded **Automations** ("always-on agents" with Slack emoji and GitHub triggers, computer-use tool); 3.9 (Jun 22) unified "plugins, skills, MCPs, subagents, rules, commands, and hooks at the user, team, or workspace level"; 3.9 (Jun 29) shipped a public-beta **iOS app** to "launch and manage always-on agents from anywhere." [Cursor Changelog](https://cursor.com/changelog)
- Teaching note: Cursor's 3.9 customization surface (skills/subagents/rules/hooks) is near-isomorphic to Claude Code's — the ecosystem is converging on the same extension vocabulary. [Cursor Changelog](https://cursor.com/changelog) · [Claude Code overview](https://code.claude.com/docs/en/overview)

### Aider — the open-source terminal OG, now slow-moving
- Aider lets you "pair program with LLMs" in the terminal; it "automatically commits changes with sensible commit messages" (git-native by design) and is model-agnostic — BYO API keys, cloud or local models. [Aider homepage](https://aider.chat/)
- Its signature context strategy is the **repo map**: a graph-ranking algorithm "computed on a graph where each source file is a node and edges connect files which have dependencies" selects "the most important identifiers, the ones which are most often referenced by other portions of the code" into a default ~1k-token map, sized dynamically. This is a *static, pre-computed* alternative to Cursor's embedding index and Claude Code's agentic search. [Repository map — aider docs](https://aider.chat/docs/repomap.html)
- **Architect/editor split**: architect mode sends the request to a reasoning "architect" model, then "sends another request to an 'editor model', asking it to turn the architect's proposal into specific file editing instructions" — an early two-model pattern that anticipated today's planner/executor agent designs. [Chat modes — aider docs](https://aider.chat/docs/usage/modes.html)
- **Currency warning for authoring:** last release is v0.86.0 (2025-08-09); the homepage still headlines Claude 3.7 Sonnet / o1-era models, and the polyglot leaderboard was last updated 2025-11-20 (top entry: gpt-5 high, 88.0%). Aider remains a great teaching artifact (repo map, git-first, architect mode) but is no longer tracking the frontier — say so explicitly. [aider releases — GitHub](https://github.com/Aider-AI/aider/releases) · [Aider LLM Leaderboards](https://aider.chat/docs/leaderboards/)

### GitHub Copilot — from autocomplete brand to agent platform
- The **Copilot cloud agent** "works autonomously in a GitHub Actions-powered environment": assign a GitHub issue, `@copilot` a PR comment, or prompt from Copilot Chat; it gets "its own ephemeral development environment... where it can explore your code, make changes, execute automated tests and linters," then presents a diff for review — humans must approve PR creation, and it never auto-merges. Available on **all paid Copilot plans**. Hard limits: max 59-minute runs, one repo / one branch / one PR per task, GitHub-hosted repos only. [About GitHub Copilot cloud agent — GitHub Docs](https://docs.github.com/copilot/concepts/agents/coding-agent/about-coding-agent)
- **Copilot CLI** is GitHub's terminal agent: conversational + autonomous modes, plan mode, `@` file references, image/PDF attachments, scheduled prompts (`/every`, `/after`), custom instructions/agents; it "may attempt to read, modify, and execute files" only after explicit folder trust, with one-time vs session-wide approvals; ships pre-configured with GitHub's MCP server, extensible via `/mcp add`. Structurally it is a Claude Code-shaped product. [Copilot CLI overview — GitHub Docs](https://docs.github.com/en/copilot/how-tos/copilot-cli/use-copilot-cli/overview)
- In VS Code, agent sessions do multi-file work ("the agent analyzes your code, makes the changes, and responds with a summary"), run "multiple sessions in parallel," and a dedicated Agents window handles "orchestrating tasks across multiple projects." [Chat in VS Code — VS Code Docs](https://code.visualstudio.com/docs/copilot/chat/chat-agent-mode)
- **The moat inverted:** GitHub now hosts *competitors' agents* as first-class citizens — "Anthropic Claude" and "OpenAI Codex" are assignable from the Agents tab, issues, PRs (`@AGENT_NAME`), and mobile; generated code is auto-scanned with CodeQL + secret scanning; usage bills as Actions minutes + AI credits. GitHub is positioning as the *venue* for agents, not just a vendor of one. [About third-party coding agents — GitHub Docs](https://docs.github.com/en/copilot/concepts/agents/about-third-party-coding-agents)

### Claude Code — our pick, for the record
- Official framing: "an agentic coding tool that reads your codebase, edits files, runs commands, and integrates with your development tools," available in terminal, IDE (VS Code/JetBrains), desktop app, and browser — one engine, shared CLAUDE.md/settings/MCP across surfaces. Distinctives students already use: CLAUDE.md memory + auto memory, skills, hooks, subagent teams, Unix-composable CLI (`tail -200 app.log | claude -p ...`), GitHub Actions/GitLab CI, Agent SDK for building custom agents. [Claude Code overview — official docs](https://code.claude.com/docs/en/overview)
- Fair-comparison note: Claude Code's historical differentiators (terminal-native, hooks, skills, subagents, MCP) each now have counterparts in Cursor 3.9 and Copilot CLI. The durable differences are model access (Anthropic-first vs router), the composable-CLI/SDK posture, and maturity of the extension ecosystem — teach students to compare on those axes, not on feature-name bingo. [Cursor Changelog](https://cursor.com/changelog) · [Copilot CLI overview](https://docs.github.com/en/copilot/how-tos/copilot-cli/use-copilot-cli/overview)

### Reading the benchmark noise
- **SWE-bench** (Jimenez et al., Princeton) is the canonical academic anchor: 2,294 real GitHub issue/PR pairs from 12 Python repos; the task is to "edit the codebase to address the issue." Historical calibration: at publication the best model (Claude 2) resolved **1.96%**; today's vendor-quoted "SWE-bench Verified" numbers sit far higher — teach students to check *which variant* (full / Lite / Verified), *what scaffold*, and *what date* before trusting any number. [SWE-bench — arXiv 2310.06770](https://arxiv.org/abs/2310.06770)
- **Aider polyglot** measures something narrower: 225 hard Exercism exercises across C++/Go/Java/JS/Python/Rust, testing edit-format compliance and instruction-following without human intervention — a *model* benchmark run inside one harness, not an *agent* benchmark. It also demonstrates staleness risk: last updated 2025-11-20. [Aider LLM Leaderboards](https://aider.chat/docs/leaderboards/)

### Teaching angle
- Frame the day as an FDE research exercise, not a product review: (1) classify each tool by form factor and context strategy, (2) verify claims against current official docs (students should discover aider's staleness and Cursor's 3.9 convergence themselves), (3) map the review/permission model of each (checkpoints vs draft-PR gate vs folder trust + approvals vs hooks/permissions), (4) close on why the team standardized on Claude Code and which axes would legitimately change that decision.

## Concept IDs

Scoped to this day (alternatives landscape + comparison axes). Claude Code internals, eval methodology depth, and multi-agent orchestration excluded.

- **`agent-form-factor-spectrum`** — IDE-fork (Cursor) vs platform extension + cloud (Copilot) vs pure terminal (Aider) vs terminal-first multi-surface (Claude Code); why form factor drives workflow more than model choice.
- **`repo-context-strategies`** — Three ways agents "know" a codebase: aider's tree-sitter graph-ranked repo map (static, ~1k tokens), Cursor's semantic embedding index, agentic on-demand search (Claude Code, Copilot CLI); tradeoffs in freshness, cost, and scale.
- **`architect-editor-split`** — Aider's two-model pattern: reasoning model proposes, editor model produces concrete file edits; precursor to modern planner/executor and subagent designs.
- **`async-delegated-agents`** — Issue-to-draft-PR delegation: ephemeral CI-hosted environments (Copilot cloud agent's Actions sandbox, Cursor cloud subagents), hard limits (59-min cap, one PR per task), and the human review gate as the safety contract.
- **`review-and-permission-models`** — How each tool constrains a semi-autonomous agent: Cursor checkpoints/rollback, Copilot folder-trust + per-command approvals + never-auto-merge, Claude Code permissions/hooks; the comparison axis that matters most for client work.
- **`coding-agent-benchmarks`** — SWE-bench (real GitHub issues; variant/scaffold/date caveats) vs aider polyglot (edit-compliance model benchmark); how to read vendor numbers and spot stale leaderboards.
